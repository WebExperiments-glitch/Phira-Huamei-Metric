# 引擎去向（2026-10-23 调研结论）

> 这份文档回答一个问题：**难度引擎接下来该往哪走。**
> 结论不是拍脑袋，是先看了两个成熟系统的实现方式，再对照我们的差距。

---

## 一、别人是怎么做的（事实，不是概括）

### osu! standard

`2025-10-29` 的官方更新说明 + osu!lazer 源码结构：

```
物件预处理 → 逐物件算难度 → strain 累积并随时间衰减
          → 每 400ms 切一段，段内取峰值
          → 各技能分别取「前 N 个峰值」按 0.9 的衰减权重加权
          → 技能值用 p-norm 合成（不是加权和）
          → 开立方根得到星数
```

几个关键细节：

- **分技能**：Aim（准星移动，且**算两遍**——含滑块位移 / 不含）、Speed（点击）、
  Reading（读谱，密度与转角）、Flashlight。各自独立的 strain 模型。
- **Aim 的峰数取 10、Speed 取 5** —— 不同技能对"峰值"的敏感度不同。
- **p-norm 而非求和**：一张只在某一维度极强的谱，结果贴近那一维；
  两维都强的谱高于任一维但低于两者之和。**这是"跳跃谱"和"技术谱"能同星的原因。**
- **开立方根**：这就是为什么 4★→5★ 与 8★→9★ 都是一星，但底层难度差得远。
- Speed 里还有**节奏复杂度**与**连打惩罚**（doubletapness），专门区分"无脑高速"和"真节奏"。

### Etterna（MinaCalc）

- 同样**逐物件**，同样输出**多个技能轴**：overall / stream / jumpstream /
  handstream / stamina / jackspeed / chordjack / technical。
- **按倍速各算一遍**（0.7x–2.0x），所以一张谱在不同 rate 下有不同难度。
- 关键一句（官方论坛）：**"No replay data involved."** —— 它是纯谱面模型，
  玩家评分是拿成绩去对这张谱的难度，而不是拿回放反推。

### 两者共同点（这才是重点）

| | osu! | Etterna | **我们** |
|---|---|---|---|
| 计算单位 | 逐物件 | 逐物件 | **整曲聚合 37 个数** |
| 有没有"记忆" | strain 衰减 | 同 | **没有** |
| 是否分技能 | 4 个 | 8 个 | 有 4 组，但是手调权重相加 |
| 聚合方式 | 取峰值 + p-norm | 取峰值 | **加权平均/截尾平均** |
| 最终数字来源 | 力学模型 | 力学模型 | **kNN 查 9509 张的声明定数** |
| 标定依据 | 长期校准 + 玩家表现 | 长期校准 | 谱师声明值（主观） |

**结论：业界主流不是"统计回归"，是"力学/应变模型"。**
两个系统都不做 kNN，都不回归聚合特征。

---

## 二、我们的差距在哪（这解释了 R² 为什么卡住）

我们已经实测过：kNN、岭回归、梯度提升树，三类模型 R² 都落在 **0.46**。
换模型没用。原因不在模型，在**表示方式丢了信息**：

1. **丢了时间顺序**
   聚合之后，"前 30 秒全是双押、后 30 秒全是单点"和"均匀双押"拿到同一组特征。
   而玩家的疲劳、爆发、读谱压力全部依赖顺序。

2. **没有记忆**
   strain 模型的核心是"累了"——难度不是物件难度的和，是**带衰减的累积**。
   同样 10 个音符，连着来和隔 2 秒来，难度差一档。聚合特征天生表达不了。

3. **目标是主观声明值**
   即便前两条修好，R² 天花板仍受标签噪声限制（见第四节）。

**所以"加更多算法"是错的解法，"换表示方式"才是。**

---

## 三、方向：三步，按顺序

### 阶段 1 —— 应变模型（替换聚合特征）

把 `engine.js` 的特征提取从"整曲聚合"改成"逐物件 + 分段"：

```
每个物件算即时难度 d_i（间隔、位移、手型、和弦大小、是否跨手）
strain_i = max(strain_{i-1} · e^(-Δt/τ), d_i)        ← 核心：衰减累积
按 500ms 分段，取每段峰值 → 得到一条难度曲线
```

**产出不是 37 个数，而是一条曲线**（时间 × 强度）。

立刻可用的产品价值：
- "第 37–52 秒是这张谱的难点"——玩家真正想知道的东西
- 难点分布图（前端画一条折线就够）

⚠ 这一步**不改压力测试的接口**（仍输出一个标量），只是中间表示变了。

### 阶段 2 —— 分技能（对齐 osu!/Etterna）

四个技能轴，各自独立 strain：

| 轴 | 即时难度的来源 |
|---|---|
| 速度 | 时间间隔、连打长度、节奏复杂度 |
| 位移 | 跨列距离、手型切换、大跳 |
| 耐力 | 长段高密度、恢复间隔是否足够 |
| 协调 | 多指同时、交叉手、长条与点击交叉 |

合成用 **p-norm**，不用加权和（加权和会互相补偿，这个坑我们在显著性判定上踩过）。

权重不手调——**用现有 9509 张的声明定数做校准**（最小二乘拟合四个轴的权重）。
注意：这是**校准**，不是 kNN。模型结构是人定的，参数由数据定。

### 阶段 3 —— 换目标（唯一能突破 0.46 的路）

用玩家成绩校准：同一张谱的 ACC 分布、通关率、失败点。

`phm_scores` 已经能存成绩了（2026-10-23 修好）。积累几百条就能开始。

这一步的价值不只是提 R²——它把"难度"从**谱师觉得多难**变成**玩家实际多难**，
这是标度语义的改变，比数值提升重要。

## 四、明确不做的事（都有实测或事实依据）

### ❌ Transformer / 深度序列模型

- 监督信号还是那批噪声标签 → 天花板不变
- 本机只有 CPU，训练几小时起步
- osu! 与 Etterna 都没走这条路，不是他们想不到，是不划算

**除非同时做阶段 3**（换成玩家行为标签），否则别碰。

### ❌ 继续换回归模型

已实测：岭回归 0.492、GBDT 0.464（p90 反而从 1.46 恶化到 1.68）。
三类模型同处 0.46，说明剩余方差在这些特征里**没有可学的结构**。

### ❌ "规则表"式专家系统

`if (连续同键 > 8) +0.5` 这种孤立规则，本质是加权重，没有记忆、没有相互作用。
和现在的 `ps.total` 是同一件事，只是更啰嗦。

**专家系统要做成"应变模型"，不是"规则清单"。** 这是这次调研最重要的区分。

---

## 五、为什么相信这条路

1. **osu! 从 2008 年迭代到现在，架构没换过** —— 一直是 strain + 分技能 + 峰值聚合。
   说明它撑得住十年演进，不是一次性方案。
2. **Etterna 的 MSD 被玩家当"绝对标度"用**（跨谱可比）；
   我们的 kNN 输出是"社区共识"（有偏、且依赖参照集）。语义层次差一档。
3. **逐物件模型天然输出"哪段难"**，这是我们目前给不了的，也是用户最想要的解释。

---

## 六、诚实的风险

**阶段 1、2 做完，R² 不一定会大幅超过 0.46。**

因为如果标签噪声占主导，任何模型都到不了更高。但即便如此，这两步仍然值得做：
- 难度曲线 = 可解释性（产品价值，独立于准确度）
- 分技能 = 输出语义更丰富（速度型 / 技术型）
- 也为阶段 3 打好基础（玩家成绩要按段落对齐才有效）

**真正的天花板突破只能靠阶段 3。** 前两步是修表示，第三步是换信号源。

## 七、下一步（可执行）

| 步 | 内容 | 产出 |
|---|---|---|
| 0 | 在 `data/` 上做一次离线原型：物件级 strain，只跑 200 张谱 | 一条难度曲线 + 与声明的相关系数 |

| 2 | 四轴 strain + p-norm，拟合权重 | v0.7 |

**第 0 步不需要上线、不需要改引擎、不需要版本号**，纯离线跑，一天能出结果。
这是最该先做的一步。

## 八、⚠ 原型实测：应变模型这条路**不成立**（2026-10-23 当晚）

写完第七节的下一步之后，我直接做了离线原型（`tools/proto-strain.mjs`），
用 Phigros 坐标算逐物件难度 → strain 双轴衰减 → 500ms 分段取峰值。

### 单变量结果（180 张）

    Spearman ρ = 0.617
    单变量拟合 R² = 0.246      ← 一个标量，对 37 维的 0.464

一个标量到这个程度不算差。**但问题不是"能不能算出东西"，是"有没有新信息"。**

### 关键实验：把应变特征加进 37 维，R² 会不会涨？

| 样本 | 只 37 维 | 37 + 8 条应变特征 | ΔR² |
|---|---|---|---|
| 270 张 | 0.7007 | 0.7010 | **+0.0003** |
| 643 张 | 0.6857 | 0.6872 | **+0.0014** |

**没有新信息。** 换句话说：应变模型算出来的东西，现有特征里**已经有了**。

### 为什么

因为 37 维里本来就有 `strain_p99` / `strain_peak` / `strain_p50` /
`strain_p90` / `strain_raw_max` / `above_avg_density_*` ——
**原始引擎早就内含一个逐音符 strain 模型**，只是当年叫"strain"没叫"应变"。

我照着 osu! 又实现了一遍，得到的是同一批信息的更粗版本。

### 结论修正

第三节的"阶段 1 / 阶段 2"**撤销**。不是因为它错，是因为它已经做过了。

剩下的判断：

| 方向 | 状态 |
|---|---|
| 逐物件 strain | ❌ 已测，等价于现有特征 |
| 分技能（速度/位移/耐力/协调） | ⚠ 大概率同样无增益（都是从同一批 strain 派生的），**没有验证就不要做** |
| jack/trill、变速、分段密度 | ❓ 未测。这类是**结构**信息，不是强度信息，可能真的缺 |
| 换目标（玩家成绩） | ✅ 唯一没被证伪的路径，也是最贵的 |

### 所以现在的正确下一步

**先测"结构类特征"有没有增益**，方法和上面一样便宜：

1. 从原始 note 序列里算 jack（同列连续最短间隔）、trill（两列交替）、
   变速幅度与次数、分段密度方差
2. 加进 37 维，看 ΔR²

如果这些也没增益 —— 那就是**标签噪声主导**，任何谱面特征都救不了，
只能走"换目标"（玩家成绩）。

**先花半天测，别先花四周做。** 这是这次调研最值钱的教训：
osu! 的架构值得学，但"我们已经有一半了"这件事，只有量过才知道。
