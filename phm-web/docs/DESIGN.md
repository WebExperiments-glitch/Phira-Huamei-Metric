# P.H.M. Standard · 设计系统与视觉立场

> 这份文档是**交给 AI 做配色/视觉方案时的输入**。
> 里面所有数值都从 `public/css/base.css` 里实测抄出（不是构想），
> 对比度用 WCAG 2.1 公式算过，结论标了「实测」。
>
> 最后两节是重点：**§8 自评与差距**、**§9 给 AI 的 brief**。

---

## 1. 这是什么产品

一句话：**给 Phira / Phigros 谱面一个「可审计」的难度参考。**

它不是一个"游戏工具站"，更像一份**测量报告**：

- 输入一张谱面，输出**两个定数**（社区共识标度 + 官谱标度）和**它们的不确定范围**；
- 全程在浏览器本地解析，**谱面文件永不上传**；
- 所有结论都带**误差与已知局限**，页面里明确写着「不判定虚标」「声称能区分就是造假」。

### 由此推出的设计立场

| 产品气质 | 视觉上必须体现 |
|---|---|
| **可审计** —— 每个数字都能追溯 | 数字用等宽数字（tabular-nums），表格是主角，不是装饰 |
| **诚实** —— 不装权威、不隐瞒误差 | 不确定度与结论**同等视觉权重**；警告/局限用中性色，不藏起来 |
| **克制** —— 是尺子，不是玩具 | 单一强调色；不用渐变、不用大圆角卡片堆叠、不堆 emoji |
| **夜里用** —— 玩家多是深夜看谱 | 深色为主；浅色是"能用"而不是"主打" |

> 反面清单（**明确不做**）：游戏化皮肤、彩色进度条满屏、拟物化、玻璃拟态滥用、
> 大面积渐变、动效炫技。这个站点的说服力来自"看起来像个仪表盘"。

## 2. 视觉三原则（现行，2026-10-07 定）

参考对象：DeepSeek 官网 / Kimi 官网 / z.ai 的设计体系。三条都是**约束**，不是风格。

### 原则 1 · 只有一个主色

> DeepSeek 的设计分析原文：**"no-secondary-accent"**。色相越多越像工具，越少越沉得住。

- 全站**唯一强调色 = 琥珀 `--brand`**，只用于「关键动作 + 品牌标识」。
- 其余一切（分面、分隔、标签、徽标底色）走中性阶梯。
- ⚠ 新增 UI 时先自问：**这个颜色必须是主色吗？** 能用中性色就别上色。

### 原则 2 · 层级靠亮度，不靠色相

> Kimi：**"hierarchy through luminance contrast rather than hue"**。

`--bg → --card → --card2 → --card3` 是一条**亮度阶梯**，
用哪一层取决于元素「浮多高」，**不是**它属于什么功能。

### 原则 3 · 靠边框分面，少用阴影

> Kimi 用 0.5px 白边框做 **"optical definition without visual weight"**。

- 边框统一走**半透明** `rgba(255,255,255,.075)`。
  半透明的好处是**自动适配任何底色层次**——不必为每种 surface 各配一个边框色。
- 阴影在深色下几乎不可见（`--sh1` 只有 `rgba(0,0,0,.35)`），
  只用于「真的浮在别的元素之上」的场景（下拉、模态）。

## 3. 色彩系统（实测值）

### 3.1 中性阶梯 —— 一条线，不是一组分类

| 令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `--bg` | `#0b0d10` | `#f7f8fa` | 画布，最底 |
| `--card` | `#12151a` | `#ffffff` | 卡片，浮一层 |
| `--card2` | `#181c22` | `#f1f3f6` | 次级面 / 行悬浮 |
| `--card3` | `#20252d` | `#e7eaef` | 输入框 / 激活态，浮最高 |
| `--fg` | `#e9edf3` | `#1a1d21` | 主文字 |
| `--fg2` | `#a3adbb` | `#4b535e` | 次要文字 |
| `--fg3` | `#6f7887` | `#7c8592` | 弱化文字 / 标签 |
| `--fg4` | `#4c535f` | `#a8b0ba` | 占位符 / 极弱 |
| `--line` | `rgba(255,255,255,.075)` | `rgba(0,0,0,.09)` | 常规边框 |
| `--line2` | `rgba(255,255,255,.13)` | `rgba(0,0,0,.16)` | 强调边框 / 分隔 |

**⚠ 温度观察（要给 AI 处理的重点）**：深色中性是**冷调偏蓝**的
（`#0b0d10` = R11/G13/B16，B 通道最高；`#12151a`、`#181c22`、`#20252d` 同样蓝偏）。
主色琥珀 `#f0b03f` 是**暖调**。冷暖对撞在这个组合里是可用的经典搭配，
但**不是 Claude 那种"同温层"的和谐**——见 §8.1。

### 3.2 主色：琥珀

| 令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `--brand` | `#f0b03f` | `#b8791a` | 唯一强调色 |
| `--brand-soft` | `rgba(240,176,63,.14)` | `rgba(184,121,26,.11)` | 选中行 / 高亮底 |
| `--brand-line` | `rgba(240,176,63,.38)` | `rgba(184,121,26,.34)` | focus ring / 选中边框 |
| `--brand-ink` | `#201705` | `#ffffff` | 主色底上的文字 |
| `--brand-hover` | `#f7bd5a` | `#a86c12` | 主色按钮悬停 |
| `--on-color` | `#0d1117` | `#ffffff` | 压在任何**亮色块**上的文字（徽标、色条） |

> **浅色下主色必须压深**：`#f0b03f` 在白底上对比度只有约 1.8:1，正文里读不清。
> 所以浅色环境的品牌色是 `#b8791a`。实测对比度见 §3.5。

### 3.3 语义色（降饱和，别抢注意力）

| 令牌 | 深色 | 浅色 | 语义 |
|---|---|---|---|
| `--ok` | `#3fb950` | `#1a7f37` | 通过 / 命中 |
| `--warn` | `#d29922` | `#9a6700` | 需注意 / 过期 |
| `--err` | `#f85149` | `#cf222e` | 失败 / 拒绝 |
| `--info` | `#58a6ff` | `#0969da` | 中性提示 |
| `--purple` | `#b083f0` | `#8250df` | 第五档位（AT/SP 区分用） |

### 3.4 图表负荷配色（四组特征，要能互相区分）

| 令牌 | 深色 | 浅色 | 代表 |
|---|---|---|---|
| `--density` | `#58a6ff` | `#0969da` | 密度 |
| `--pattern` | `#b083f0` | `#8250df` | 结构 |
| `--coord` | `#f0b03f` | `#b8791a` | 协调（= 主色） |
| `--stamina` | `#3fb950` | `#1a7f37` | 持续 |

> ⚠ 这一组是全站**唯一允许多色**的地方：图表要能区分系列，色相是信息。
> 但四色**整体降饱和**，避免变成玩具色卡。

### 3.5 对比度实测（WCAG 2.1）

| 配对 | 深色 | 浅色 | 判定 |
|---|---|---|---|
| `--fg` on `--bg` | **16.56** | **15.92** | AAA ✓ |
| `--fg2` on `--bg` | 8.57 | 7.32 | AAA ✓ |
| `--fg3` on `--bg` | **4.37** | **3.51** | ⚠ 仅 AA-large |
| `--fg4` on `--bg` | **2.51** | **2.06** | ✗ **不达标** |
| `--brand` on `--bg` | 10.18 | 3.41 | 深 AAA / 浅 AA-large |
| `--brand-ink` on `--brand` | 9.26 | 3.63 | 深 AAA / 浅 AA-large |
| `--ok` on `--bg` | 7.66 | 4.78 | AAA / AA ✓ |
| `--warn` on `--bg` | 7.71 | 4.58 | AAA / AA ✓ |
| `--err` on `--bg` | 5.80 | 5.04 | AA ✓ |
| `--info` on `--bg` | 7.70 | 4.89 | AAA / AA ✓ |

**两个真实的弱项（不是猜测，是算出来的）：**

1. **`--fg4` 严重不达标**（2.51 / 2.06，门槛 4.5）。
   它只用在 placeholder 上，那种场景 WCAG 允许放宽，**但 2.5:1 意味着
   在阳光下、或对比度差的屏幕上基本读不出来**。这是一个明确的改进项。
2. **`--fg3` 差一点到 AA**（深色 4.37 vs 门槛 4.5；浅色 3.51 更远）。
   而它正好用在 **11.5–12px 的小标签**上 —— 小字最需要对比度，这里反而最低。
   浅色主题尤其明显。

## 4. 字体系统（现状 + 待决）

### 4.1 现状（实测）

```css
/* 正文 —— 纯系统栈，没有任何 webfont */
font: 14px/1.65 -apple-system, BlinkMacSystemFont, "Segoe UI", system-ui,
      "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;

/* 等宽 —— 只用于数字与代码 */
--mono: ui-monospace, "SF Mono", "Cascadia Code", Consolas, monospace;
```

- **行高 1.65** 是刻意留给 CJK 的（DeepSeek 的设计体系写了
  「1.6 body line-height，deliberate CJK accommodation」）。
- 数字用 `font-variant-numeric: tabular-nums` —— 表格里数字要对齐。
- ⚠ **只有一套字体。** 没有 display/body 的层级对比，中英也没有分别指定。
- ⚠ 服务器 CSP 是 `font-src 'self' data:` —— **只能用自托管字体**，不能挂 CDN。

### 4.2 问题

用户反馈原话：**「字体好像也是用的默认的。给换一种好看的字体。」**

技术上的根因很明确：**系统栈在不同平台上长得完全不一样**——
Windows 上落到 Microsoft YaHei（偏旧、字重层次弱），iPad 上是 PingFang SC（好）。
同一个网站在两台设备上是两种气质，这对"要做成品牌"是致命的。

### 4.3 三个方案（待用户拍板）

| 方案 | 代价 | 效果 | 适合 |
|---|---|---|---|
| **A · 中文子集自托管** | 约 500KB～1MB（按站内实际用字裁剪） | 中英文**都换**，效果最明显 | 追求品牌一致 |
| **B · 只换拉丁（Inter 变体）** | 约 100KB | 英文/数字明显变好，**中文几乎不变** | 轻量优先 |
| **C · 只优化系统栈** | 0 | 排序变好、开字体特性；**Windows 上变化有限** | 零成本 |

> **我的判断**：这个站点**正文以中文为主**，所以只做 B 等于没换。
> 要做品牌一致性，只有 A 是有效解 —— 但必须**按站内用字裁剪**
> （全量 Noto Sans SC 是 10MB+，不可接受）。
> 参考实现路径：提取全站 HTML + i18n 字典里的唯一汉字 →
> `pyftsubset` 裁成 woff2 子集 → 自托管 → `font-display: swap`。
>
> **对标参考**：Claude 用的是「衬线 display + 无衬线正文」的双字体组合；
> Apple 用的是单一家族（SF Pro）但靠**字重与光学尺寸**拉层级。
> 两者都不靠"换一个花哨字体"，而是靠**家族内的层级对比**。
> 这一点比选哪个字体更重要 —— 见 §8.2。

## 5. 尺寸系统

| 类别 | 令牌 | 值 |
|---|---|---|
| **圆角** | `--r-sm` / `--r` / `--r2` / `--r3` | 6 / 10 / 14 / 18px（**只用这四档**） |
| **间距** | `--sp1…--sp7` | 4 / 8 / 12 / 16 / 24 / 32 / 48px（8px 网格，小值 4px 起） |
| **字阶** | `--t-xs…--t-3xl` | 11.5 / 12.5 / 13.5 / 15 / 18 / 22 / 28 / 36px |
| **阴影** | `--sh1` / `--sh2` | `0 1px 2px rgba(0,0,0,.35)` / `0 6px 20px rgba(0,0,0,.45)` |
| **动效** | `--ease` | `cubic-bezier(.4, 0, .2, 1)` |

> ⚠ 规矩：**不要临时写 `13.7px` 这种值**。字阶、圆角、间距都只用令牌里的档位。
> 这条有 lint 在管（`tools/lint-slop.mjs` 的硬编码颜色/尺寸规则）。

## 6. 组件规范摘要

| 组件 | 规矩 |
|---|---|
| **按钮** | 三种权重：`primary`（主色底 + `--brand-ink` 文字）/ 默认（中性底 + 边框）/ `sm`（小尺寸）。悬停只改**一个**属性（边框色或底色），不做位移 |
| **卡片** | `--card` 底 + `--line` 边框 + `--r2` 圆角。**不叠阴影**，靠边框分面 |
| **表格** | 数字列右对齐 + `tabular-nums`；表头可点排序；行悬浮用 `--card2` |
| **档位徽标** | 五档固定色（EZ/HD/IN/AT/SP）；识别不出时显示**「未标注」而不是 `?`** |
| **空状态** | **必须说明原因**（"这个账号没上传过谱面"），不是干巴巴一句"暂无数据" |
| **数据缺失** | 能确定原因就说原因。**尽量不用孤零零的 `—` 或 `?`** |
| **导航** | 滚动后启用**毛玻璃**（哨兵元素 + IntersectionObserver，不监听 scroll） |
| **术语** | 黑话（RKS / B19 / p99）第一次出现时**可点开看**，不删术语也不留给用户猜 |

## 7. 双主题的实现纪律

- 语义名**两套完全一致**，只换值 —— 页面代码一行不改。
- 切换落在 `<html data-theme="dark|light">`；用户的**选择**另记在 `data-theme-mode`（auto/dark/light）。
- **防闪烁**：每个页面 `<head>` 里有一段**同步内联**脚本，执行早于样式表
  （模块是异步的，等它跑完页面已经按默认色画过一帧 = FOUC）。
- **浅色不是"把深色反相"**：主色必须压深、`--on-color` 必须反白、
  滚动条滑块要单独给值、`color-scheme` 要跟着切（否则表单控件还是深色）。

## 8. 自评：对标 Claude 与 Apple 的差距

### 8.1 配色：结构是对的，**温度不统一**

| 维度 | P.H.M. 现状 | Claude | 差距判断 |
|---|---|---|---|
| 强调色数量 | 1（琥珀） | 1（陶土橙系） | **持平** ✓ |
| 中性色温度 | **冷调偏蓝**（B 通道最高） | **暖调纸质**（米白/暖灰） | **明显差距** |
| 主色 vs 中性 | 暖色撞冷底 | 同温层 | **最大的一处不和谐** |
| 浅色主题 | 冷灰 `#f7f8fa` | 暖米白（近 `#F0EEE6`） | **明显差距** |

> **结论**：P.H.M. 的中性阶梯**结构**（一条亮度线、半透明边框、少阴影）是专业的，
> 不比 Claude 差。差的是**色温**：暖琥珀压在一个偏蓝的黑上，
> 而 Claude 之所以"高级"，很大程度上是因为**所有中性色都在同一个色温家族里**。
>
> 这是**给 AI 做配色的第一个、也是最值得改的问题**：
> 让中性阶梯带上一点点暖调（例如从 `#0b0d10` 移到 `#0d0c0b` 这一侧），
> 与琥珀主色同温层。改动很小，气质变化很大。

### 8.2 字体：**层级只靠颜色，没靠字体本身**

| 维度 | P.H.M. 现状 | Claude / Apple | 差距判断 |
|---|---|---|---|
| 字体家族数 | 1 套 sans + 1 套 mono | Claude：display + body 两套；Apple：一套但拉满字重 |
| 层级手段 | 主要靠 **`--fg` / `--fg2` / `--fg3` 换色** | 主要靠 **字重 + 字号 + 光学尺寸** | **明显差距** |
| 字阶跨度 | 11.5 → 36px，正文 13.5px | 更大、更敢用大字 | 中等差距 |
| 平台一致性 | Windows 与 Apple 是两种气质 | 全平台一致 | **明显差距** |

> **结论**：现在"层级"是靠**把字调灰**实现的 —— 而调灰到 `--fg3`(4.37:1) /
> `--fg4`(2.51:1) 时，可读性已经受损（§3.5 实测）。
> Claude/Apple 的做法是：**颜色保持高对比，用字重和字号做层级**。
> 这既更好看，也**顺便解决了对比度不达标的问题**。
>
> 这是给 AI 的第二个关键建议：**把层级从"颜色"迁移到"字重 + 字号"。**

### 8.3 已经做对、不要动的

- 单一强调色（原则 1）✓ 与 Claude 一致
- 亮度阶梯做层级（原则 2）✓ 与 Kimi/DeepSeek 一致
- 边框分面而非阴影（原则 3）✓ 与 Kimi 一致
- 数字等宽对齐、空状态解释原因、术语可点开 ✓ 这些是**产品的诚实气质**，
  比视觉更值钱，改配色时**不要牺牲它们**。

## 9. 给 AI 的配色 brief（可直接粘贴）

> 下面这段是自包含的。想换配色时，把整段发给任何 AI 即可。

```
我要给一个叫 P.H.M. Standard 的网站改配色。它的定位是
「Phira 谱面难度测量报告」——像仪表盘，不像游戏。

【硬约束 · 不可违反】
1. 只能有一个强调色，不要引入第二个色相做强调。
2. 层级靠亮度（surface 阶梯）而不是色相。
3. 分面靠边框而不是阴影；边框必须用半透明 rgba，不能用实色。
4. 必须同时给出深色与浅色两套，语义名一一对应、只换值。
5. 浅色主题下强调色必须压深到能在白底上读清。

【现状令牌（要改的对象）】
深色：bg #0b0d10 / card #12151a / card2 #181c22 / card3 #20252d
      fg #e9edf3 / fg2 #a3adbb / fg3 #6f7887 / fg4 #4c535f
      line rgba(255,255,255,.075) / line2 rgba(255,255,255,.13)
      强调 #f0b03f（琥珀）
浅色：bg #f7f8fa / card #ffffff / card2 #f1f3f6 / card3 #e7eaef
      fg #1a1d21 / fg2 #4b535e / fg3 #7c8592 / fg4 #a8b0ba
      强调 #b8791a
语义色：ok #3fb950 / warn #d29922 / err #f85149 / info #58a6ff（深色）

【已知问题 · 请在方案里解决】
A. 中性色是冷调偏蓝（B 通道最高），而强调色是暖琥珀 —— 温度不统一。
   参考 Claude：它的高级感来自"所有中性色在同一色温家族"。
B. fg3 对比度 4.37:1（深）/ 3.51:1（浅），低于 WCAG AA 的 4.5，
   而它正用在 11.5px 的小标签上 —— 小字最需要对比度。
C. fg4 对比度 2.51:1（深）/ 2.06:1（浅），用于 placeholder，太低。

【请输出】
1. 一套新的深色 + 浅色中性阶梯（各 4 层 surface + 4 级文字）
2. 与之同温层的强调色（保留"琥珀/暖金"方向，但如果移动到别的橙金区间请说明理由）
3. 每组关键配对的 WCAG 对比度数值（fg/fg2/fg3/fg4 on bg，强调色 on bg，
   强调底上的文字 on 强调色），并标注是否达标
4. 一句话说明这版配色的色彩策略（它想传达什么气质）

【验收标准】所有正文文字 ≥ 4.5:1；小标签 ≥ 4.5:1；占位符 ≥ 3:1；
强调色上的文字 ≥ 4.5:1；深浅两套都要满足。
```
