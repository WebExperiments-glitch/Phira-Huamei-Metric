# 音频节拍 / 鼓 / 钢琴分离：可复用开源项目

> 目标：替代“只看总 onset”的做法。规则引擎需要分开：
> 1) 节拍/BPM；2) 鼓点；3) 钢琴/旋律点。
> 只列可查许可证的项目；MIT 优先。

## MIT（可直接复用）

| 项目 | 语言/形态 | 能做什么 | 备注 |
|---|---|---|---|
| [chrisguttandin/web-audio-beat-detector](https://github.com/chrisguttandin/web-audio-beat-detector) | JS / Web Audio | BPM + 拍点 | 浏览器可直接用；适合替换当前自相关 BPM |
| [facebookresearch/demucs](https://github.com/facebookresearch/demucs) | Python / PyTorch | 4-stem 分离（drums/bass/other/vocals） | MIT；有预训练权重；离线跑鼓轨最稳 |
| [deezer/spleeter](https://github.com/deezer/spleeter) | Python / TensorFlow | 2/4/5-stem 分离 | MIT；4-stem 有 drums，钢琴在 other |
| [sigsep/open-unmix-pytorch](https://github.com/sigsep/open-unmix-pytorch) | Python / PyTorch | 音乐源分离 | MIT；可训练/微调 |
| [Music-and-Culture-Technology-Lab/omnizart](https://github.com/Music-and-Culture-Technology-Lab/omnizart) | Python / TF | beat、drum、piano、chord 转写 | MIT；直接出鼓/钢琴事件，适合做 onset 真值 |

## 建议落地

### 浏览器零依赖（当前页面）
- 节拍：vendor web-audio-beat-detector（MIT），替换当前手写 BPM 估计。
- 鼓/钢琴：继续用当前分频段 + 谱平坦度 heuristic；它只是分流，不是真正的源分离。

### 本地高质量（离线，Python）
1. demucs 分离出 drums.wav 与 other.wav。
2. 对 drums.wav 做 onset → 鼓点。
3. 对 other.wav 做 onset / omnizart piano → 钢琴点。
4. 用规则引擎按 2K / 参考谱参数生成 .pez。

> 真正“分辨鼓声/钢琴”需要源分离或转写模型；纯 FFT 频段只能做粗分流。

## 已实际安装 / 跑通

- `web-audio-beat-detector` 8.2.39（MIT）已 vendored 到 `public/vendor/web-audio-beat-detector/beat-detector.mjs`，页面 BPM 交叉校验。
- `.venv-audio` 安装了 `demucs 4.1.0`（MIT）；`htdemucs` 首次运行下载约 80MB。
- 30 秒参考音频实测：CPU 约 21–25 秒完成 `drums.wav` / `no_drums.wav` 分离。
- 离线管线：`node tools/ai-chart.mjs --audio song.mp3 --out song.pez`。
  流程：Demucs 分轨 → ffmpeg f32 → 鼓/钢琴 onset → 规则谱 → .pez。

## 当前实现状态

- audio-analysis.js 已输出总 onset、drumOnsets、pianoOnsets。
- 鼓：低频 kick + 高频噪声 + 谱平坦度。
- 钢琴：中频谐波 + 低平坦度。
- BPM：60–200 网格搜索 + 半拍/IOI 修正；参考曲 190 BPM。
