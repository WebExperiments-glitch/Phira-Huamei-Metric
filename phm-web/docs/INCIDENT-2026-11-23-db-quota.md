# 事故记录 · 2026-11-23 · 数据查询全线不可用

> 状态：**部分未修复**（数据库侧需人工处理）
> 影响：依赖数据库的查询功能；**算定数不受影响**

---

## 一、现象

BetterStack 七个监控同时转红，状态页显示全线故障。
但站点首页、`/app`、`/chart/*`、`/status` 全部返回 **200**。

人工复测发现三种响应并存：

| 端点 | 返回 |
|---|---|
| `/api/v1/meta` | 200（不查库） |
| `/api/v1/charts/22681` | **429** rate_limit_exceeded |
| `/api/v1/analyses/probe` | **503** `db:false` |

BetterStack 的事件原因也分成两类：`Status 503`（4 个）与
`Timeout (no headers received)`（2 个）。

---

## 二、根因（两层，互相放大）

### 层 1：数据库额度超限（致命，未修复）

直连数据库返回：

```
53000  Your account or project has exceeded the quota.
```

- 项目：`ep-super-union-az4say68`（ap-southeast-1 / neondb）
- 这不是代码问题。额度用尽后**所有查询连接被拒**。
- 与 2026-10-21 腾讯云 `DATABASE_RESOURCE_ISOLATED` 是同一类事故，换了供应商但机制相同。

**处理方式**：需要到 Neon 控制台确认超的是哪个维度（计算时间 / 存储 / 传输），
再决定升级计划还是清理数据。**代码侧无法绕过。**

### 层 2：探针把自己的额度打爆（已修复）

站点匿名额度 `apiAnonHour = 100`，**按 subject（IP）计**。
BetterStack 有 4 个探测区域（eu / us / as / au），7 个监控 × 每 300 秒
⇒ 每区域约 **84 次/小时**。

84 距 100 只剩 16 次余量。真实访客进来就溢出 → 429。

更糟的是**恶性循环**：
1. 数据库挂了 → 探针收到 503/超时 → 判定为宕机
2. 监控持续探测，其中 `/analyses/probe` **每次都会查库**
3. 在 Neon 免费计划的自动挂起机制下，每次探测都唤醒一次数据库
4. 数据库越被唤醒，计算额度消耗越快 → 更难恢复

---

## 三、已做的修复

| 项 | 改动 | 依据 |
|---|---|---|
| 5 个非 DB 探针 | 300s → **600s** | 每区域 30 次/小时，留足访客余量 |
| 2 个 DB 探针 | 300s → **1800s** | 每区域 1 次/小时，减少无谓唤醒 |
| `tools/fix-monitors.mjs` | 增加频率修正能力 | 原来只改 URL |

修复后每区域合计约 **31 次/小时**，安全线 100 以下。

**没有做的**：给探针加 API Key。
理由：key 要存到第三方控制台，且走 key 额度 1000/h——
为了 7 个探针占用一把长期凭据，收益不抵风险。

---

## 四、影响范围（如实）

| 功能 | 状态 |
|---|---|
| 算定数（拖入谱包，浏览器本地算） | ✅ 正常 |
| 谱面包下载 | ✅ 正常 |
| 页面浏览 / 版本页 / 状态页 | ✅ 正常 |
| 谱面搜索、全库统计 | ❌ 不可用 |
| 玩家 / 谱师查询 | ❌ 不可用 |
| 按需分析（PoW 换分析） | ❌ 不可用 |
| 谱面详情页的「P.H.M. 定数」 | ⚠️ 降级（缓存读不到，需实时算） |

核心功能是纯前端计算 + 静态参照集（`ref-com.json` 2.1MB 仍可正常下载），
所以「算定数」这条主链路**没有受影响**。这是 2026-10-21 那次收敛决策的回报。

---

## 五、待办

1. **人工**：登录 Neon 控制台，确认超限维度并处理（升级 / 清理 / 等重置）。
2. 恢复后观察：监控应在一轮检查周期内自动转绿，无需手动 resolve。
3. 结构性改进（未做）：DB 探针应当**不查库**，只读进程内状态，
   否则「监控数据库」这件事本身会消耗数据库额度。
4. 结构性改进（未做）：匿名额度与监控探针共用 subject，
   任何一方暴涨都会误伤另一方。正确做法是给探针一条独立通道。

## 六、对外通告文案

> **标题**：数据查询服务资源受限，部分功能暂不可用
>
> 上游数据服务已触及资源配额上限，依赖它的查询类功能暂时不可用。
>
> 受影响：谱面搜索、全库统计、玩家与谱师查询、按需分析。
> 不受影响：算定数（纯本地计算）、谱面包下载、页面浏览。
>
> 同时修正了健康检查的探测密度——此前探针请求高于匿名访问配额，
> 检查本身会被限流并误报为宕机。
>
> 资源侧恢复后本页会自动更新。

关于「安全」的部分刻意写得笼统：只说明探测密度与配额的冲突，
不披露具体额度数值、供应商、以及密钥形态。
