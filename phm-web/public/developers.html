P.H.M. API

Phira / Phigros 谱面难度参考接口。查询已缓存的定数，或分析一张谱并写入共享缓存。 免费；匿名可用，API Key 获得更高额度。

返回的是「点估计 + 不确定带」：ref_const 是模型估计标度， ref_official 是官谱标度。两者不可混比，细节见首页说明。

快速开始

API 是普通的 HTTPS + JSON，不需要 SDK。先拿到一个 API Key（开放平台），或者直接用匿名额度试：

# base_url https://phm.app.workbuddy.host/api/v1 # 匿名也可以，只是额度低 curl https://phm.app.workbuddy.host/api/v1/charts/22681

带 Key 的请求（推荐 x-phm-key）：

curl https://phm.app.workbuddy.host/api/v1/charts/22681 \ -H "x-phm-key: sk-你的key"

JavaScript：

const res = await fetch( "https://phm.app.workbuddy.host/api/v1/charts/22681", { headers: { "x-phm-key": "sk-你的key" } } ); const chart = await res.json();

Python：

import requests r = requests.get( "https://phm.app.workbuddy.host/api/v1/charts/22681", headers={"x-phm-key": "sk-你的key"}, timeout=30, ) print(r.json())

在线试一下

不用装任何东西，在这里直接打一次真实的请求。Key 可以留空 —— 留空就走匿名额度。

点「发送请求」看结果。
Key 只存在这个输入框里，不写入 localStorage、不进 URL。 请求头用的是 x-phm-key —— 这也是你该用的那个头。

认证

两种身份：

  • 匿名：不带任何鉴权头，按真实对端 IP 限流（100 次/小时）；
  • API Key：x-phm-key: sk-<32 位十六进制>（推荐）， 也可用 Authorization: Bearer sk-…（兼容，但可能失效，见下）。
为什么必须用 x-phm-key：本站部署在一个会改写鉴权头的网关后面， 实测两种常见写法都不可靠 ——
① Authorization：网关会写入它自己的值，把你的盖掉；
② x-api-key：网关把它当成自己的鉴权头消费掉，服务端收不到；
③ x-phm-key：私有名字，网关不碰，稳定生效。
失效时的表现很隐蔽：不报错，只是静默降级成匿名（1000 次/小时 → 100 次/小时）。
自检方法：把 Key 换成一把不存在的 sk-（格式仍要对）， 正常应返回 401 invalid_api_key；如果仍返回 200， 说明 Key 没送达，你正在以匿名身份被限流。
更直接：打开 /api/v1/meta?diag=1， 看 diag 里各头的长度 —— 0 表示这个头没穿透到服务端。

Key 的明文只会在创建时返回一次；服务端只存 sha256 哈希与掩码。每个账号最多 100 个有效 Key，可随时吊销。

开放平台登录使用站点账号；API Key 与账号密码相互独立，不要把 Key 写进前端代码或公开仓库。

限流

身份额度说明
匿名100 次/小时真实对端 IP + 全局桶
API Key1000 次/小时分析另有 200 次/天

超限返回 429，并带 retry-after；服务端限流器不可用时返回 503。

查询定数

GET /charts/{chart_id}

读共享缓存。未分析过的谱返回 analyzed:false（不是 404）。

{ "chart_id": 22681, "name": "Pandemic", "level": "IN.16", "difficulty": 16.6, "ref_const": 15.6, "ref_official": 16.1, "ps_score": 13.4, "engine_ver": "server-verified", "engine_build": "com-trim15-v0.5.0", "analyzed": true, "cached": true }

列出谱面

GET /charts

分页浏览共享缓存。这是唯一能"不知道 id 也能用"的接口 —— /charts/{id} 需要你先知道是哪张谱，而这里可以搜索、排序、翻页。

参数默认说明
page1页码，从 1 开始
pageSize50每页条数，上限 200
sortchart_id排序字段，白名单：chart_id / name / level / difficulty / ref_const / ref_official / ps_score / nps / notes。传别的值返回 400
orderascasc 或 desc
q—按谱面名做子串匹配（最多 60 字符）
level—难度前缀过滤，如 IN / AT / SP
only—official = 只要算得出官谱标度的；stale = 引擎版本与基准不一致的
build—判过期用的基准引擎版本，仅在 only=stale 时有意义
curl "https://phm.app.workbuddy.host/api/v1/charts?sort=ref_const&order=desc&pageSize=3" \ -H "x-phm-key: sk-你的key"

响应（total 是真实总数，不是本页条数，可以直接算页数）：

{ "rows": [ { "chart_id": 80464, "name": "QuomodocunquizE", "level": "AT Lv.19", "ref_const": 17.834, "ref_official": 16.9645, "ps_score": 16.623, "nps": 19.3434, "notes": 4000, "engine_build": "com-trim15-v0.5.0", "analyzed": true, "cached": true } ], "total": 661, "page": 1, "pageSize": 3, "pages": 221, "sort": "ref_const", "order": "desc" }

全库统计

GET /stats

共收录多少谱、覆盖多少、活跃用户多少。与首页展示的数字同源。

curl https://phm.app.workbuddy.host/api/v1/stats \ -H "x-phm-key: sk-你的key" # → {"charts":661,"scores":81,"profiles":1,"active_1d":1,…}

谱师作品

GET /charters/{uid}

某个谱师（Phira 用户 id）上传过的谱面，并自动贴上本站已算好的定数。

参数默认说明
uid（路径）必填Phira 用户 id，纯数字
maxPages3向上游读几页（每页 30 张），上限 5 —— 硬上限，避免这个接口变成爬虫入口
curl "https://phm.app.workbuddy.host/api/v1/charters/257272?maxPages=2" \ -H "x-phm-key: sk-你的key" # → { "uid":257272, "count":2, "returned":2, "maxPages":2, # "charts":[ { "chart_id":48099, "name":"Future Downloader", # "analyzed":false, … } ] }
两个必须知道的行为：
① analyzed:false 表示本站还没算过这张谱 —— 此时 ref_const 等字段不存在。缺字段和"算出来是 0"是两件事，别用 0 兜底。
② 上游挂了返回 502，不会返回空数组。空数组会被读成"这位谱师没有作品"， 那是最坏的错误答案 —— 宁可报错让你重试。

玩家资料

GET /players/{uid}

公开资料 + 统计。不含成绩明细：把几百条记录塞进一个响应，既慢又容易被批量抓。

curl https://phm.app.workbuddy.host/api/v1/players/257272 \ -H "x-phm-key: sk-你的key" # → { "id":257272, "name":"平方秒和立方吨", "rks":3.5926006, # "bio":"…", "avatar":"https://…", "joined":"2023-07-25T…", # "stats":{ "numRecords":850, "avgAccuracy":0.9449… } }

uid 不存在返回 404 player_not_found。 stats 是可选增强：拿不到时为 null，请求本身仍然成功。

分析谱面

POST /analyses

服务端从 Phira 下载谱面、复算并写入共享缓存。v1 只接受 chart_id；分析结果对之后所有查询直接可用。

curl -X POST https://phm.app.workbuddy.host/api/v1/analyses \ -H "x-phm-key: sk-你的key" \ -H "content-type: application/json" \ -d '{"chart_id": 22681}'

已缓存时直接返回（cached:true）；未缓存时会下载 ≤60MB 谱面并运行引擎，可能需要几秒。并发上限 2，忙时返回 503 analysis_busy。

用量

GET /usage

用 API Key 调用时返回该 Key 所属账号的用量；开放平台用账号 token 调用也可以。

{ "today": 12, "week": 87, "month": 312, "by_endpoint": { "/charts": 280, "/analyses": 32 }, "quota": { "hourly": 1000, "analysisDaily": 200 } }

Key 管理

在 API 开放平台 登录后创建、改名、设置权限/到期、轮换、吊销。删除（吊销）后 Key 会立即从列表消失，历史用量仍保留。

Scopes（7 个）：charts:read（查询、标称差）、 analyses:write（分析）、usage:read（用量）、 behavior:read（玩家实测难度）、reference:read（社区参照集）、 engines:read（引擎权重）、system:read（状态 / 事件 / 版本）。 缺 scope 返回 403 insufficient_scope；过期返回 401 expired_api_key。 创建时可设 30/90/365 天或永不过期；轮换会新建同权限 Key 并立即吊销旧 Key。
方法路径说明
GET/keys列出当前账号的有效 Key（吊销后不再返回；不含明文）
POST/keys创建，返回一次明文；body 可带 scopes[] / expires_in_days
PATCH/keys/{id}改名 / 改 scopes / 改到期
POST/keys/{id}/rotate轮换：新 Key + 吊销旧 Key
DELETE/keys/{id}吊销

这些接口要求网页账号 token（x-hm-token），不是 sk- key。

只读数据端点 v1.3

这一批把站内本来就能看到、但第三方只能整包下载的数据，变成可查询、可限流、可审计的接口。 全部只读，不写库、不触发重算、不接受上传。数据源都是本站已在公开路径上的 JSON 与站内自检模块。

方法 / 路径Scope说明
GET /behaviorbehavior:read玩家实测难度。1,700 张谱 ≥10 人打过，17,000 名玩家的 15.8 万条成绩按 log(std) 双向固定效应反推；数据文件含 4,532 条。?chart_id= 单查，?limit=&offset= 分页（1..500）。
GET /referencereference:read社区参照集 ref-com.json：9,508 行 × 36 维特征。同样的单查 / 分页；每行展开成具名字段。
GET /enginesengines:readengine-v2 / v3 / v4 与 seq-model 的元数据（维数、目标、字节数）。
GET /engines/{id}engines:read取回某一版权重的原始 JSON，用于复现实验。
GET /versionssystem:read从 CHANGELOG.md 真源解析的版本列表（version / date / current）。
GET /statussystem:read与站内状态页同一份 24h 快照：20 个目标的可用率、组件状态、进行中的事件。
GET /incidentssystem:read进行中的故障 + 最近 10 条历史，来自 Statuspage 决策树那套组件状态。
GET /discrepancycharts:read标称 vs 实测：可比谱数、|delta| 中位数、超过 1 / 1.5 级的张数。?chart_id= 或 ?min_gap=。
关于 discrepancy：ref_const 与 ref_official 基于两套标度， delta 仅供对照坐标，不是误差指标。这与站内页面的口径一致。

示例

curl https://phm.app.workbuddy.host/api/v1/behavior?chart_id=4 \ -H "x-phm-key: sk-你的key" { "found": true, "chart_id": 4, "behavior_difficulty": 9.04, "sample_size": 19, "notes": 459, "duration_s": 115.5, "bpm": 134 }

notes / duration_s / bpm 是谱面指纹——页面靠它把没有 chart_id 的本地谱面对上号。

连通性探测 v1.3

公开、无需 Key（要探的就是「能不能连上」），但仍计入匿名限流，避免被当成免费探针放大器。 逐项探测 database / phira-upstream / local-data / status-monitor， 返回每项的 ok 与耗时（毫秒）。

curl -i https://phm.app.workbuddy.host/api/v1/health { "ok": true, "checkedAt": "2026-11-08T…", "checks": [ { "name": "database", "ok": true, "ms": 201 }, { "name": "phira-upstream", "ok": true, "ms": 893 }, { "name": "local-data", "ok": true, "ms": 0 }, { "name": "status-monitor", "ok": true, "ms": 0 } ] }
关于「单独开一个端口」：本站部署在只暴露一个 HTTP 端口的托管环境里，物理上开不了第二个。 所以用专用端点代替，语义等价：第三方定时打 /health， 200 = 全通，503 = 至少一项依赖不可达（端点本身仍活着）。 响应只回 ok / ms / 分类，不回内部主机名、连接串或上游正文。

请求证明与防控 v1.4

API 是公开的，但「公开」不等于「无限」。匿名访问完整保留， 只读接口照旧可用；被收紧的只有一件事：匿名不能再触发谱面重算 （下载谱面 + 跑引擎是全站最贵的操作，之前相当于免费算力放大器）。

档位怎么获得配额能做重算吗
anon什么都不带100/h，突发 12/10s不能
keyx-phm-key: sk-…1000/h，突发 25/10s能（200/天）
signedHMAC 签名 或 DPoP 证明2000/h，突发 40/10s能
adminPHM_ADMIN_SECRET + 时间戳签名2000/h管理 Key
兼容承诺：所有增强都走可选请求头。一个头都不带的现有匿名客户端、 以及现有 sk- Key 客户端，行为完全不变（除了匿名重算被收口）。 GET /api/v1/meta 的 guard 字段会自述当前启用了哪些能力。

① HMAC 请求签名

x-phm-ts: <毫秒时间戳> x-phm-nonce: <8..128 字符，一次性> x-phm-sig: base64url(HMAC-SHA256(base, secret)) x-phm-signer: <可选，调用方标识> base = METHOD + "\n" + PATH + "\n" + sha256(body) + "\n" + ts + "\n" + nonce PATH 是去掉 query 的完整路径，例如 /api/v1/analyses（含 /api/v1 前缀）

时间戳允许 ±5 分钟，nonce 用后即弃（10 分钟内不可复用）。 密钥取 PHM_HMAC_SECRET；未显式配置时由服务端写入凭据派生， 那条路只面向可信的内部服务端——要开放给第三方，请显式配置并分发该值。

② DPoP 自包含证明（推荐给第三方）

不需要注册、不需要预先交换密钥：客户端自己生成一对 P-256 密钥，把公钥放进请求头即可。

x-phm-proof: base64url(header).base64url(payload).base64url(sig) header = { "alg":"ES256", "typ":"dpop+jwt", "jwk": { 客户端公钥 JWK } } payload = { "htm":"GET", "htu":"/api/v1/charts", "iat": <毫秒>, "jti": <一次性 UUID>, "jkt": <可选，公钥指纹> } sig = ES256 签名，覆盖 header + "." + payload

服务端验签、核对 htm/htu、检查 iat 与 jti 重放。 带 sk- Key 时还会把公钥指纹与该 Key 绑定，之后换密钥即拒绝。

③ PoW 挑战 / 行为熵 / 诱捕

只对匿名生效。请求间隔异常均匀（或亚毫秒连发）时返回：

HTTP 428 Precondition Required { "challenge": { "seed":"…", "bits":2, "expires_at":"…" } }

求一个十六进制 nonce 使 sha256(seed + ":" + nonce) 以 bits 个 0 开头，重发时带 x-phm-pow: <nonce>。 难度默认 2（约几百次哈希，浏览器毫秒级）。连续失败会转入极轻量的诱捕响应， 不查库、不跑引擎——耗的是攻击者的时间，不是我们的算力。

④ 管理员密钥

/keys（创建 / 轮换 / 吊销）除账号 token 外，新增一条独立通道：

x-phm-admin: <PHM_ADMIN_SECRET> x-phm-ts: <毫秒时间戳，±60s> x-phm-sig: base64url(HMAC-SHA256("admin:" + ts, PHM_ADMIN_SECRET))

未配置 PHM_ADMIN_SECRET 时该通道关闭，账号 token 路径照旧。 绝不会回退到服务端内部密钥。

环境变量

变量默认作用
PHM_HMAC_SECRET从写入凭据派生HMAC 签名密钥
PHM_ADMIN_SECRET空（关闭）管理员通道
PHM_POW / PHM_ENTROPY / PHM_DECOY开置 0 分别关闭
PHM_POW_BITS2难度，1..4
无状态部署的边界：nonce / jti / 行为记录都在进程内，重启即清空。 这是刻意的取舍——宁可重启后重新观察，也不把安全状态放进不可用的外部存储。 若需要跨进程防重放，应把这三张表挪到共享存储，属于后续重构。

压力与降级 v1.5

限流解决的是「某个调用方用太多」；这一层解决的是所有人一起用，或者服务被打—— 每个调用方都没超自己的额度，但总在途请求和下游延迟已经爆了。那种时候继续一视同仁地接， 结果就是全部变慢直到连状态页都打不开。

所以我们按成本选择性放弃，而不是平等地接住所有请求：

成本档包含压力下
cheap/meta /engines /versions /behavior /reference /analyses/probe永不放弃 —— 它不碰数据库，是「服务还活着」的最后证据
normal/charts /charts/{id} /stats /discrepancy压力大时先对匿名降额，持 Key 保留
expensive/charters/{uid} /players/{uid} POST /analyses最先被牺牲（打上游 / 跑引擎）

牺牲顺序是 匿名 → API Key → 签名 / 管理员。也就是说：压力期持 Key 的第三方还能用， 签名请求与管理员通道始终保留（那是运维通道，砍掉等于自断手脚）。

HTTP 503 Service Unavailable Retry-After: 5 { "error": { "type": "server_error", "code": "load_shedding", "message": "server is under load; retry shortly" } }

GET /api/v1/meta 的 load 字段会实时暴露压力 （level / inflight / p50 / shedTotal）。 看到 level 变成 busy 或 critical 但接口还通， 说明降级在工作 —— 这时候请退避重试，不要立刻重发。
