# 手型（A_extent）特征规格 v1 —— Python 与 JS 的单一事实来源

> 2026-11-05 · 对应 `tools/handshape_features.py`（Python）与 `tools/build_handshape_extent.py`（切片）
> 目标：浏览器端（纯 JS）照着本文逐条实现，结果与 Python **逐位一致**（容差 1e-6）。
> 依据实验：`docs/结果/片段手型特征-A-B.md`（46 指标全量里只有这 8 个值钱）。

---

## 0. 一句话

把谱面事件按「连续 8 / 16 个」或「0.5s / 1s 时间窗」切成**互不重叠的片段**，
对每段算 **8 个描述"这段摊开多大"的标量**，再对整张谱的片段序列取 **8 个统计量**，
得到 **4 × 8 × 8 = 256 维**，追加在现有 142 维池化之后（合计 398 维）。

**只做这 8 个指标。** 转向/曲率/换手/同押/节奏/密度（38 个指标）实测无效，不进生产。

---

## 1. 输入

| 项 | 定义 |
|---|---|
| 事件 | `(t, x_note, sx, sy, rot, type, above, hold)`，来自 `chart_io.load_notes_ex` |
| `t` | 秒（浮点） |
| `x_note` | `positionX`（±675 谱面坐标）—— **本规格不用它** |
| `sx, sy` | 判定线运动/旋转后的**屏幕坐标**，与 675 同尺度 |
| 坐标归一 | 所有长度 ÷ 675（半屏宽） |
| 排序 | 先按 `t` 升序，`t` 相同的按 `sx` 升序（左→右）。Python 用 `np.lexsort((xs, t))`，**稳定排序** |
| 事件上限 | 8,000（与数据集一致；超出部分丢弃） |
| 最少事件 | 全谱 < 4 个事件 → 直接输出 256 个 0 |

> `sy` 恒为 0 的谱（PEC 全部 723 张、以及没有 moveY 的 RPE）不影响正确性：
> `aspect` 分母有 +1 平滑，不会出 inf；语义上退化成 `span_x·675`。

## 2. 片段切法（4 种，互不重叠）

设排序后事件时间为 `t[0..n-1]`。

| 代号 | 规则 |
|---|---|
| `n8` | 下标 `[0,8), [8,16), …`，不足 8 个的尾巴丢弃 |
| `n16` | 下标 `[0,16), [16,32), …`，尾巴丢弃 |
| `t05` | 分箱 `b = floor((t[i] − t[0]) / 0.5)`，同一 `b` 的事件为一个片段 |
| `t10` | 同上，窗宽 1.0 秒 |

时间窗是**从首音符起算**、按全局时间轴等宽划分，不是滑窗；一个片段内的事件数不固定。

**片段丢弃条件**：事件数 `< 4` → 该片段不计（指标无意义）。丢弃后若一个片段都不剩，
该谱在对应切法下的 8 个统计量全为 0。

## 3. 片段内 8 个指标（唯一需要的）

对片段内的事件序列 `(x_i, y_i), i=0..m−1`（`x = sx/675`、`y = sy/675` 已归一）：

```js
dx[i] = x[i+1] - x[i]        // i = 0..m-2
dy[i] = y[i+1] - y[i]
L[i]  = hypot(dx[i], dy[i])  // 步长
```

| # | 指标 | 公式 | 说明 |
|---|---|---|---|
| 1 | `path` | `Σ L[i]` | 路径总长（半屏宽为单位） |
| 2 | `disp` | `hypot(x[m−1] − x[0], y[m−1] − y[0])` | 首尾直线位移 |
| 3 | `eff` | `disp / (path + 1e-9)` | 路径效率；1 = 直线，越小越绕 |
| 4 | `bbox_area` | `rx * ry` | 包围盒面积 |
| 5 | `diag` | `hypot(rx, ry)` | 包围盒对角 |
| 6 | `aspect` | `rx / (ry + 1.0)` | 宽高比。**+1 是"675 单位"的平滑项，不是 1e-9** |
| 7 | `span_x` | `rx` | x 极差（手型横向跨度） |
| 8 | `span_y` | `ry` | y 极差 |

其中

```js
rx = max(x) - min(x)
ry = max(y) - min(y)
```

> ⚠ **2026-11-05 更正（原文写错了）**：`aspect` 的 `rx / (ry + 1.0)` 是在**原始坐标**上算的，
> 不是在除过 675 的坐标上算的。后者会差 675 倍（`aspect` 实测在 100~1000 量级，不是 0~1）。
> （即 1.0 = 整个半屏宽），照抄 `rx / (ry + 1.0)` 即可，不要再乘 675。

## 4. 谱级 8 个统计量

对每个指标的**片段值序列** `v[0..S−1]`（`S` = 该切法下保留下来的片段数）：

| 统计量 | 定义 |
|---|---|
| `mean` | `Σv / S` |
| `std` | **总体**标准差：`sqrt(Σ(v−mean)² / S)`（ddof=0，不是 S−1） |
| `min` / `max` | 最小 / 最大 |
| `p10` / `p50` / `p90` | 线性插值分位数，见下 |
| `skew` | `m3 / m2^1.5`，`m2 = Σd²/S`、`m3 = Σd³/S`、`d = v−mean`；`m2 ≤ 1e-18` 时取 0；结果裁 `[−20, 20]` |

线性插值分位数（与 `numpy.percentile` 默认、与现有 `pool142` 同口径）：

```js
function quantile(sortedV, q) {          // sortedV 升序
  const n = sortedV.length;
  if (n === 0) return 0;
  if (n === 1) return sortedV[0];
  const h = (n - 1) * q;
  const lo = Math.floor(h);
  const hi = Math.min(lo + 1, n - 1);
  return sortedV[lo] + (sortedV[hi] - sortedV[lo]) * (h - lo);
}
```

`S == 0` → 8 个统计量全 0（**不要**输出 NaN）。

## 5. 向量布局（256 维，顺序是契约，禁止重排）

```
index = ((segIdx * 8) + statIdx) * 8 + metricIdx
```

- `segIdx ∈ {0:n8, 1:n16, 2:t05, 3:t10}`
- `statIdx ∈ {0:mean, 1:std, 2:min, 3:max, 4:p10, 5:p50, 6:p90, 7:skew}`
- `metricIdx`（**固定顺序**）：
  `0:path, 1:disp, 2:eff, 3:bbox_area, 4:diag, 5:aspect, 6:span_x, 7:span_y`

即第 0 维是 `n8|mean|path`，第 7 维是 `n8|mean|span_y`，第 8 维是 `n8|std|path`，……
第 255 维是 `t10|skew|span_y`。

> 这一顺序来自 `METRIC_NAMES` 的原始顺序（path/disp/eff 排在 bbox 之前），
> **不是**字母序、也不是实验文档表格里的顺序。逐维名字以
> `data/handshape-extent-v1.npz::names` 与 `phm-web/public/data/engine-v4.json::handshape.names` 为准，
> JS 侧应写一个 256 项的对拍测试。

## 6. 与模型拼接

```
X = [ pooled142 , extent256 ]           // 398 维
z = clip((X − mu) / sd, −8, +8)          // ⚠ 必须裁 ±8，见下
b = z · w + b0
ding = 1.12 * b + 15.99                  // 与 v3 相同的 b→定数映射
```

`mu / sd / w / b0` 在 `engine-v4.json`（字段 `clip_z = 8`）；`pooled142` 的算法与 v3 完全一致
（20 维事件特征取 mean/std/min/max/p10/p50/p90 + 事件数 + Σdt）。

**为什么必须裁 ±8**：398 维里有十几列在某个训练集上近似常量（如 `n8|max|bbox_area`
在训练集里几乎全 0）。`sd + 1e-6` 会把 1e-4 的偏离放大到 z≈4,000，单列就能把 b 推到 −20。
实测切分 12345 未裁剪时短谱预测 sd 5.2、MAE 0.744（基线 0.529）；裁剪后短谱 ρ 在
三个切分上**全部更高**、MAE 全部更低（见 `docs/结果/手型特征-生产模型.md`）。
JS 端漏掉这一步会得到"看起来能跑、个别谱离谱"的结果。

## 7. 复杂度与实现要点

- 单谱 **O(n log n)**：排序一次；片段内全 O(k)，`k ≤ 16` 或时间窗内事件数；
  每个指标对 `S` 个片段值排序一次（8 × 4 = 32 次排序）。
- 内存 O(n)。Python 实测 **0.12 s/谱**（平均 940 事件）；JS typed array 预计同量级。
- 只用算术、`sqrt`、`hypot`、排序、比较。没有矩阵、没有随机数。
- **不要**用 `Math.hypot` 之外的花式写法替代 `hypot`（浮点结果会有 1e-16 级差异，可接受；
  但 `sqrt(a*a+b*b)` 在极大值上会溢出，`hypot` 不会）。

## 8. 已知近似（必须写进产品说明，不许假装精确）

1. `chart_io._track_value` **只做线性插值**，忽略 RPE 的几十种 `easingType`。
   `start == end` 的保持型事件是精确的；曲线缓动会产生偏差。
2. `load_notes_ex` 的 `sx/sy` 用「取第一个非空 eventLayer」的近似（`line_geometry.py`
   里有按 prpr 语义求和的精确版，生产暂未启用）。
3. PEC 谱没有判定线运动信息：`sx = x_note, sy = 0`，`aspect` 退化为 `span_x · 675`。
4. 12 张 `eventLayers` 含 `null` 的谱在 v1 缓存里被填 0；`handshape-extent-v1.npz`
   已用修复后的 `chart_io` 重算真值（本规格与 v1 缓存数值完全一致，抽样 20 张 max|Δ| = 0）。
