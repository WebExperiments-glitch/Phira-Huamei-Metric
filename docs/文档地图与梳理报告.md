## 1. 项目速览

**一句话**：P.H.M.（Phira Huamei Metric）—— 给 Phira / Phigros 谱面算「可审计的难度参考值」的工具，输出**点估计 + 不确定带 + 双标度**，明确不判定虚标。

**两个仓库、两套引擎、两类文档**：

| 维度 | 站点 / 网页版 | 桌面 / CLI |
|---|---|---|
| 代码位置 | `phm-web/`（根仓库子目录） | `phm/`（根仓库） |
| 引擎 | `phm-web/public/js/engine.js`，8 维、社区参照 9,508 + 官谱 1,037、截尾均值、双标度 | `phm/core.py`，4 维、官谱参照 1,037、加权中位 |
| 文档 | `phm-web/docs/`（8 篇，面向线上产品与运维） | `docs/`（22 篇，面向研究、离线数据与算法史） |
| 版本轴 | `phm-web/CHANGELOG.md` + 页面 `app-version` | 无独立版本，跟随站点/脚本 |
| 当前状态 | 线上 V0.12.0.0，http 200 | 可跑，`pipeline.py --status` 正常 |

**最重要的认知**：`docs/` 与 `phm-web/docs/` 不是同一套文档的两层，而是**两个产品面的两套文档**。前者记录「为什么这么做 / 数据从哪来 / 哪些实验失败了」，后者记录「线上服务怎么跑 / 怎么改 / 怎么发版」。混淆这两者，就会拿 2026-10-05 的研究结论去解释 2026-10-17 的线上行为。

## 2. 权威矩阵（冲突时以谁为准）

| 事实类型 | 唯一真源 | 说明 |
|---|---|---|
| 版本号 | `phm-web/CHANGELOG.md` | 四段式；页面/包的版本从它派生。用户向历史另有 `public/js/versions.js` |
| 操作纪律 / 发版红线 | `phm-web/docs/HANDOVER.md` | 每条红线后面跟一次真实事故 |
| 系统结构 / 数据流 / 分层 | `phm-web/docs/ARCHITECTURE.md` | 站点表与 lib 分层表是高频过期点（现已纳入 `lint-docs` 自动检查） |
| 数据库表 / RPC / 权限 | `phm-web/docs/DATA-MODEL.md` **+ 实际数据库** | `hm_*` 列清单来自代码实际读写；库与文档不一致时以库为准并回写 |
| 信任边界 / 安全状态 | `phm-web/docs/SECURITY.md` | 「尚未解决」清单需要随修复更新 |
| 网页引擎算法与选型 | `phm-web/docs/ENGINE-EXPERIMENT.md` | 所有被否掉的方案与数据都在这里 |
| 桌面 / CLI 引擎算法 | `docs/结果/点估计k-NN.md` + `phm/core.py` | 只对 `phm/core.py` 有效，**不适用于网页引擎** |
| 谱面格式 / 语料契约 | `docs/规范/谱面格式规范.md`、`docs/规范/数据飞轮契约.md` | 内容嗅探、双字段一致性等硬事实 |
| 产品定位 / 对外口径 | 根 `README.md` | 不写死版本号，指向 CHANGELOG |
| 跨会话约定 | `.workbuddy/memory/MEMORY.md` | 本机工作记忆，不入库；事实性内容应回写到上述文档 |

**防复发机制**：`node tools/lint-docs.mjs`（77 条断言）检查死链、版本号四处一致、
ARCHITECTURE 页面表覆盖 `public/*.html`、ARCHITECTURE + 开发 README 覆盖 `lib/` 与 `public/js/`。
加页面 / 加模块 / 发版后不同步文档，它会红。
