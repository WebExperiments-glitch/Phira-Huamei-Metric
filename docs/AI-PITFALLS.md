# AI 踩坑清单（本仓库专属）

> 这份文件只记**我们真的犯过、且代价可量化**的错。
> 通用编程建议不收——那些框架自己会拦。
> 每一条都对应一次返工，新条目请写明：症状 → 根因 → 怎么防。

---

## A. 结论类错误（会导致方向跑偏，最贵）

### A1. 只搜"我的方案好在哪"，5 次搜索思路都没变
- **症状**：整晚在换架构（Transformer → LNN/SSM → 分块扫描），ρ 不动。
- **根因**：真正的瓶颈是**输入特征缺了移动距离/和弦/夹角**，不是模型。
- **怎么防**：搜 5 次思路没变 = 5 次都白搜。要搜"别人怎么做"，不是搜"我为什么对"。

### A2. 先问"什么决定成败"，再动手优化
- **症状**：花 3 小时调参，收益 0.003（噪声级）。
- **根因**：没先确认瓶颈在哪。
- **怎么防**：动手前先写一句"这次要改变的指标是什么、它现在被什么卡住"。

### A3. 把"假设"当"已知"写进任务书
- **实例 1**：我告诉代理"改类型标签不影响 20 维数值"。实际两处映射互为反向，
  只改一处会让 flick/drag 的 one-hot 与 strain 权重互换。
- **实例 2**：我说"短谱差是标注瓶颈"。实测 split-half 信度短 0.9784 / 长 0.9817，
  几乎相同，标签噪声只占 2.2%。方向完全错了。
- **怎么防**：任务书里写"这是我的假设，先验证再动手"。代理有权推翻。

### A4. 只有 ρ 没有 MAE（或反过来）
- **症状**：某版短谱 ρ 更高，但预测 sd 5.2、MAE 0.744。
- **根因**：特征里有近似常量列，`sd+1e-6` 把数值放大成灾难。ρ 是序关系，看不出尺度坏了。
- **怎么防**：ρ 与 MAE 必须同时报。两者背离时先查特征尺度。

## B. 实现类错误（会让结果全错，且不易察觉）

### B1. 变量名覆盖
```python
for sd in seeds:          # sd 覆盖了上面算好的特征标准差数组
```
- **症状**：三个 seed 跑出 0.8294/0.8209/0.8340，看起来稳。
- **实际**：三个 seed 各用了 /1 /2 /3 三种错误缩放——**方差在比预处理，不在比初始化**。
- **怎么发现**：checkpoint 重载后 ρ 从 0.829 掉到 0.661。
- **怎么防**：种子变量命名 `seed`，标准差命名 `std`；关键数组加长度断言。

### B2. 排序错位
- **症状**：首版 ρ=0.03，看起来像"序列模型完全无效"。
- **根因**：`predict` 按序列长度排序输出，标签没跟着排。
- **怎么防**：任何"排序后输出"的函数，返回 (key, value) 或断言 key 对齐。

### B3. 编码/口径在两处互为反向
- `chart_io.TYPE_MAP = {1:T, 2:H, 3:D, 4:F}` 与 `to_feats` 的 `{"F":3,"D":4}` 互为反向，
  互相抵消。只改一处 = 静默交换 flick/drag。
- **怎么防**：这类成对映射，改的时候必须**两边同时改 + 跑金标证明 md5 不变**。

### B4. 静默丢数据
- PEC 谱解析后没排序 → dt 出现负值被 clamp 成 0 → 723 张谱的密度与 strain 全错
  （Σdt 膨胀 5.6 倍）。
- `_line_tracks` 不跳过 null 图层 → 12 张谱整张解析失败被丢弃，**且都是最大的几张**。
- **怎么防**：解析后必排序；`None` 元素必判；报"实际参与训练的谱数"，掉一张都要解释。

### B5. 用长度当版本标识
- PhiraiAd 的缓存键是 `bytes:{len}:{format}`，不是内容哈希。同字节数的改动不会失效。
- 我们自己也踩过：同名部署两次 → 用户端永久空白。
- **怎么防**：版本标识一律用内容哈希或显式版本号。

## C. 流程类错误

### C1. `git reset --hard` 冲掉别人的未提交改动
- **2026-11-05**：冲掉了另一个代理的 4 处修复（PEC 排序、null 图层、`extra=` 参数、类型映射），
  其中两处是 723 张和 12 张谱的 bug。
- **怎么防**：reset 前 `git status` + `git stash list`；多代理并行时**先提交再同步**。

### C2. 代理只把结论写在消息里，没落盘
- **症状**：消息里说"已成 0.8162"，磁盘上没有对应权重文件。
- **怎么防**：完成 = 磁盘有文件 + 有可复现命令。口头结论不算。

### C3. 代理互审超过 3 轮
- 实测会陷入自我循环（有项目一夜互审 50+ 轮）。
- **怎么防**：第 3 轮起只看新增 diff，不重复报已提的问题。

### C4. 把"没验证"包装成"已验证"
- 实例：仓库 `data/irt-reliability.json` 存 split_half 0.9999（n=1258），
  用当前数据重跑得 0.9801（n=11283），**复现不出**。而这个数被别的文档引用过。
- **怎么防**：任何进文档的数字，必须能一条命令重跑出来；复现不了的标注"待核"。

---

### D4. 岭回归忘了中心化 y（MAE 凭空放大 3 倍）
- **症状**：自己重写 A/B 脚本，ρ 0.52、MAE 1.39，而同一份数据在验证过的管线里是 ρ 0.80、MAE 0.44。
- **根因**：`w = solve(XtX + αI, Xty)` 没减 `y.mean()`、预测没加回截距。
  预测均值恒为 0，而 b 的均值约 −1.5 → MAE 被抬高约 1.5，ρ 也跟着掉。
- **怎么防**：**不要重写已验证的管线**。要重写就先跑一遍基线，复现不出已知数字就不许往下做。

### D5. 秩函数写成 `argsort(argsort(x))`
- **症状**：ρ 系统性偏低。
- **根因**：这只在有并列值时才接近平均秩，且实现细节与 `scipy.stats.rankdata('average')` 不同。
- **怎么防**：ρ 一律用平均秩实现（仓库里 `ab_screen_coords.rankdata` 是正确的，直接复用）。

### D6. 在子集上量出来的「效应」当成真效应
- **症状**：2,500 张子集（n_test=375）测得「同谱泄漏让 ρ 虚高 0.0224」，
  全量 7,504 张（n_test=1,126）重跑后差值变成 **−0.0136（方向反了）**。
- **根因**：n=375 时 ρ 的 SE≈0.033，0.0224 只有 0.7 SE，本来就该判为噪声。
- **怎么防**：**报任何 Δ 之前先算 SE**。n≈1,100 时 SE(ρ)≈0.015，n≈375 时≈0.033。
  Δ 小于 1.5×SE 一律写「无显著差异」，不许写「虚高 / 提升 / 恶化」。

## D. 指标与统计


### D1. 拿单次跑的好数字当结论
- 单次 +0.014、CI 跨 0，曾被当成提升写进文档。
- **怎么防**：n≈1,000 时 ρ 的 SE≈0.031，0.03 以内是噪声。必须配对 bootstrap + 至少 3 个 seed。

### D2. 用测试集选 epoch
- 对照项目 `ssm_seq.py` 用测试集选 epoch → 0.8162 是乐观值。
- **怎么防**：只用训练集内部切分选超参，测试集最后看一次。

### D3. 独立复现 ≠ 换随机种子
- 三个 seed 共享同一批谱、测试集高度重叠，只能排除"某次 permutation 的偶然"，
  **排除不了"换一批谱失效"**。写结论时必须带上这个边界。
