# 序列模型 vs 岭回归

> 2026-11-05 · 数据集 `seq-dataset-v0.1-beta.2.npz`（7,504 张 · 9,335,999 事件 · 20 维）
> 代码 `tools/train_seq_model.py`（训练）· `tools/eval_seq_calib.py`（校准+配对）· `tools/export_seq_model.py`（导出）

---

## 一句话结论

**值。** 在同一批 1,126 张测试谱上：

- **单个模型**：ρ 均值 **0.8245**（3 seed，sd 0.0040），Δρ **+0.027**（逐 seed +0.0201 ~ +0.0271）
- **3 个 seed 的预测取平均（集成）**：ρ **0.8323**，Δρ **+0.0325**，95%CI **[+0.0176, +0.0504]，下界 > 0**

岭回归同口径为 0.7998。**不管按单模型还是集成算，判据都满足。**

增益不是靠"某一次跑出好看的数"：**3 个 seed 单独做配对检验，3/3 的 CI 下界都 > 0**
（最差 +0.0016，最好 +0.0126）。而且增益随谱长单调上升（短谱 +0.010 / 中谱 +0.036 / 长谱 +0.059），
方向和「顺序信息只在长谱上积累得多」的机制预期一致 —— 这是它不像噪声的最强证据。

参数量 **34,306**（上限 100,000），CPU 训练 18 分钟/seed，单谱推理中位 17 ms。

## 一、要回答的问题

岭回归的 142 维是 **7 个分位数 × 20 维 + 事件数 + Σdt**。它把整条时间轴压平了：

```
一首 2 分钟的谱 → 20 维特征的 p10/p50/p90 → 142 个数
「第 40 秒有一段 12 连、之后空 8 秒、再来一段慢速长条」
                              ↑ 这句话在 142 维里不存在
```

20 维特征 + 142 维池化已经把 **±250ms 局部密度、1 秒窗口密度、running strain**
这些量算进去了 —— 但它们是**整谱统计**。剩下的唯一维度是**顺序**：
密度什么时候高、高多久、间隔多长、退坡是陡的还是缓的。

本实验只测这一件事。

## 二、架构

```
事件序列 (T, 20)   T 中位 1,092 / 最大 8,000
   │
   │  每 8 个事件 → 1 个 token（≈0.8 秒，中位谱 → 约 137 个 token）
   │  token = [20 维 × 8 个事件的原始值 (160) ‖ Σdt ‖ 有效比例]  = 162 维
   ▼
Linear 162→64 → LayerNorm → GELU                       10,432
   │
   ▼
深度可分离卷积 k=5（跨约 4 秒，先把相邻片混一次）          4,480
  h = h + Conv1×1(GELU(DepthwiseConv(h)))
  LayerNorm
   │
   ▼
双向 GRU, 单向 hidden 32（合计 64）                     18,816
   │
   ▼
attention pooling（学习一个 query，不是 mean）               65
   │
   ▼
LayerNorm → Linear 64→1                                  129
   │
   ▼
标量（标准化难度 z），× σ + μ 还原为 b
```

**参数量 34,306**（全部 24 个张量，明细见附录 A）。

### 三个刻意的设计选择

| 选择 | 理由 |
|---|---|
| **片内保留 20×8 原始值，不取均值** | 均值会把「这一片里有一个跳跃距离 0.8 的甩手」抹平，而尖峰正是难度来源。前作 `ssm_seq.py` 用的是组内均值，这里改成完整保留 |
| **额外喂 Σdt 与有效比例** | 同是 8 个音符，挤在 0.3 秒和摊在 2 秒难度完全不同。卷积只看见 8 个等距 token，看不见这件事 |
| **8 事件/片** | 中位谱 1,092 事件、均值 1,244（≈120 秒）→ 片长约 0.8 秒，正好是「节奏型」的尺度（十六分连打、双押群）。更大的片会开始吃掉顺序信息，更小的片 CPU 跑不动 |
| **attention pooling 而非 mean** | 难段是稀疏的，平均会把尖峰抹平 |
| **双向 GRU 而非单向** | 「这一段后面接不接得上」也算难度（呼吸段之后的爆发比平铺爆发更难）。难度是整谱属性，不存在因果约束，不需要因果掩码 |

### 为什么不用原始长度直接上 GRU

CPU 实测（14 线程，L≈1,280）：

| 配置 | 参数量 | 分钟/epoch |
|---|---|---|
| biGRU h=32，原始长度 L≈1,250 | 13,793 | **7.7** |
| biGRU h=48，原始长度 L≈1,250 | 30,289 | **11.8** |
| 本方案：patch 8 后 L/8≈160 | 34,306 | **1.2** |

原始长度下 30 epoch 要 4 小时，迭代不动。patch 化是唯一能在 40 分钟内跑完全量的口径。
（顺带一提：torch 2.11 的 **XPU 在这台机器上比 CPU 慢 4 倍**，3.7 分钟/epoch，没有用。）

## 三、切分与选择协议（与前作不同，请先看这里）

| 项 | 本实验 | 前作 `ssm_seq.py` |
|---|---|---|
| 外层切分 | `rng(20261028).permutation` → 前 85% 训练 / 后 15% 测试 | 同 |
| 训练 / 测试 | 5,741 / **1,126** | 6,378 / 1,126 |
| epoch 选择 | **训练集内部再切 10%（637 张）**，测试集只在最后看一次 | **用测试集选**（乐观偏差） |
| 岭回归 | 同样只吃 5,741 张，α=10，无超参 | — |

序列模型需要验证集选 epoch，岭回归不需要。为了**训练数据量可比**，岭回归也只喂 5,741 张 ——
这对岭回归是**不利**的（少 637 张）。多给数据的版本作为参照另列：ρ 0.8024，与本仓库文档记录的 0.8024 一致。

> 换句话说：下面 +0.0325 的差值是在「岭回归吃了同样多数据」的前提下测的，
> 不是靠多吃/少吃样本换来的。

## 六、配对 bootstrap（1,000 次，只重采样测试集）

### 6.1 三个 seed 的预测取平均（集成）vs 岭回归

| 指标 | Δ（序列 − 岭回归） | 95% CI | 序列胜率 |
|---|---|---|---|
| **ρ** | **+0.0325** | **[+0.0176, +0.0504]** | **1.000** |
| MAE | −0.0281 | [−0.0433, −0.0134] | — |
| MAE（校准后） | −0.0373 | [−0.0525, −0.0231] | — |

**CI 下界 +0.0176 > 0 → 判据满足：「确实更好」。**

### 6.2 单个 seed 各自配对（这才是"一个模型"的诚实数字）

| seed | Δρ | 95% CI | CI 下界 > 0？ | ΔMAE | 95% CI |
|---|---|---|---|---|---|
| 1 | +0.0269 | [+0.0126, +0.0450] | ✅ | −0.0197 | [−0.0351, −0.0054] |
| 2 | +0.0271 | [+0.0130, +0.0429] | ✅ | −0.0182 | [−0.0342, −0.0026] |
| 3 | +0.0201 | [+0.0016, +0.0400] | ✅（勉强） | −0.0133 | [−0.0315, +0.0050]（跨 0） |

**3/3 单独显著（ρ）。** 最差的一个 +0.0016，仍在 0 以上。
注意 seed3 的 MAE 增益 CI 跨 0 —— **MAE 的改善不如 ρ 稳，不要宣称 MAE 显著更好**。

### 6.3 方差

ρ = [0.8267, 0.8269, 0.8199]，**均值 0.8245，sd 0.0040**。

对比参考：`docs/调研/PhiraiAd-源码调研.md` 里那份 27,713 参数 / 373 训练集的模型，
自报 MAE 0.52，同谱 5 折 sd 0.54 —— **方差大于偏差**。
本模型 sd 0.0040：单模型 Δρ 约 0.027，是 sd 的 **6.8 倍**；最差一个 seed 也有 5.0 倍。
所以「+0.027」不是种子抽奖 —— 换初始化换不出这个差值。

## 七、增益从哪来：按谱长分组（3 seed 集成）

| 组 | 事件数 | n | 岭回归 ρ | 序列 ρ | Δρ |
|---|---|---|---|---|---|
| 短 | 55–925 | 376 | 0.7064 | 0.7158 | **+0.0095** |
| 中 | 927–1,327 | 375 | 0.7193 | 0.7555 | **+0.0361** |
| 长 | 1,329–8,000 | 375 | 0.8171 | 0.8764 | **+0.0593** |

**单调上升**，正好是机制预期的形状：
分位数池化对短谱损失小（样本少、分布集中），对长谱损失大
（2 分钟里"什么时候难"被压成一个 p90）。序列模型补的就是这一块。

如果增益来自过拟合噪聲，它不会刚好按谱长排序。

> 附带一个反直觉现象：**短谱的 ρ 绝对值最低（0.71）**，两类模型都是。
> 这与本仓库既有的 T6"短谱 0.670 是最短板"结论一致 —— 短谱的难度本来就更依赖玩家记忆和谱面细节，
> 不是模型没学到。

## 八、与 69k SSM（ρ 0.8162）比

| 项 | 本模型 | SSM（前作） |
|---|---|---|
| ρ | **0.8245** | 0.8162 |
| 参数量 | **34,306**（−50%） | 69,187 |
| epoch 选择 | 内部验证集 | **测试集**（乐观） |
| 增益来源 | 顺序（patch 序列） | 顺序（4 事件/组的扫描） |

**本版更好：+0.0083，且参数量只有一半，且没有在测试集上选模型。**
如果按同一乐观口径（在测试集上挑最好 epoch），本模型还能再高一点 —— 但没有做，也不该做。

差异的结构性解释：SSM 的第一步是 `GroupStem`，把 4 个事件**取均值**再进模型；
本模型把 8 个事件的 **160 个原始值全保留**，尖峰信息没被平均掉。

## 九、踩过的两个坑（都会让结论全错，记在这里）

### 坑 1：评测时预测值与标签错位

`make_batches` 按长度排序来减少 padding。第一版 `predict` 直接 `np.concatenate`
收集各批输出，得到的是**长度排序**的预测，拿去做 Spearman 时和标签对不上：
ρ = 0.03，看起来像"序列模型完全无效"。

修法：按 `idx` 的原始位置回填（`predict()` 里 `pos[i]`）。修完 ρ 立刻从 0.03 变成 0.82。

### 坑 2：`for sd in seeds` 把标准化数组覆盖了

主循环变量名叫 `sd`，和上面的特征标准差数组 `sd` 撞名。
结果 seed 1/2/3 分别用了 `(x−μ)/1`、`/2`、`/3` 三种**不同的错误缩放**，
跑出来的 0.8294 / 0.8209 / 0.8340 看起来还挺好，但**三个 seed 的方差是在比预处理，不是在比初始化**。
而且 checkpoint 无法复现（重载后 ρ 从 0.829 掉到 0.661 —— 这个不一致是发现问题的线索）。

修法：改名 `seed_k` + 加断言。**上面报告的全部数字都来自修复后的重跑。**

## 十、上线代价

| 项 | 岭回归 | 序列模型 |
|---|---|---|
| 单谱推理（CPU，中位） | **3.17 ms** | 17.3 ms（纯 numpy）/ 28.5 ms（torch 单样本，含堆叠开销） |
| 权重体积 | < 100 KB | **736 KB**（float64 文本）；改成 float32 + 6 位小数约 400 KB（未做） |
| 运行时依赖 | 无（纯算术） | 无（纯算法，见下） |
| 可解释 | ✅ 每特征一权重 | ❌ |

**可移植性已验证**：`tools/export_seq_model.py` 用纯 numpy 重写了一遍前向，
与 torch 输出最大绝对误差 **1.5e-07**。需要的算子只有 6 个：

1. `matmul + bias`（Linear）
2. `LayerNorm`（mean/var，eps=1e-5）
3. `GELU`（**erf 版**，不是 tanh 近似；numpy 版用的是 A&S 7.1.26 多项式，误差 < 1.5e-7）
4. `Conv1d`：depthwise k=5 pad=2（逐通道一维卷积）+ pointwise k=1
5. `GRU`（双向，PyTorch 门序：r, u, n；`n = tanh(W_in x + b_in + r ⊙ (W_hn h + b_hn))`）
6. `softmax + 掩码加权求和`

**不需要 ONNX、不需要 WebGPU、不需要 WASM。** 全部是 double 数组上的循环。

## 十一、结论与建议

### 判据复核

| 判据 | 结果 |
|---|---|
| Δρ 的 95% CI 下界 > 0 | ✅ 单模型 +0.0016（最差 seed）/ 集成 +0.0176 |
| 3 个 seed 的方差 | ✅ sd 0.0040，是单模型 Δρ（0.027）的 1/7 |
| 与 SSM 0.8162 对比 | ✅ 更好（单模型 +0.0083 / 集成 +0.0161），参数少一半，无测试集泄漏 |
| 覆盖率 | ✅ 1,126/1,126，零丢弃 |

### 值不值得做成「深度计算」档

**值得，但只作为可选档。**

理由：

1. **增益是真的**：单模型 +0.027（CI 下界 +0.002 ~ +0.013），集成 +0.0325（CI [+0.018, +0.050]）。
   3/3 单独显著，且按谱长单调 —— 三个独立证据方向一致。
2. **机制清楚**：补的是分位数池化必然丢失的顺序信息，不是黑箱涨点。
3. **代价可接受**：34k 参数、17 ms/谱、纯 JS 可实现、权重 736 KB（可压到约 400 KB）。
4. **但**：ρ 0.8245 vs 0.8024 的差距，落到定数上约 **0.03 个 b ≈ 0.03 分**（定数公式斜率 1.12），
   在玩家实测噪声（同谱分半信度之外的那部分）以下。**默认路径仍应该是岭回归**：
   快 5 倍、小 7 倍、可解释。

建议的产品形态：

```
默认档（岭回归）   浏览器即时算，无感
深度档（序列模型） 用户点「精确计算」时，300ms 预算内跑完
                  单模型 17 ms/谱 → 直接可用；集成要跑 3 遍（51 ms），
                  多出的 0.008 分不值得 3 倍延迟，建议只部署单模型
不建议用它替换默认档 —— 换来的 0.03 分不值 400~700 KB 和 5 倍延迟。
```

如果哪天要压延迟：GRU 那 18,816 个参数占了 55%，可以把双向改成单向（省一半、掉 ρ 约 0.003），
或者把 patch 从 8 加到 16（token 减半、延迟近似减半）。两条都没试，不要当结论。

### 如果还要继续

只剩两件事有信息量，都不是"换架构"：

1. **正则化**：现在 ep>8 就过拟合。加 dropout 0.2 / 提高 weight decay，可能让有效 epoch 从 3 拉到 10，
   ρ 或许 +0.005。**但这只是把同样的信息挖得更干净，不是新信息。**
2. **长谱专项**：Δρ 在长谱段是 +0.059，短谱只有 +0.010。如果能解决短谱（ρ 0.71），
   整体收益比继续堆长谱大得多。但短谱的瓶颈大概率是标注而非模型（T6 一直是 0.67–0.71 的墙）。

**不建议**：更大的模型。5,741 张训练集已经把 34k 参数喂到过拟合了。
