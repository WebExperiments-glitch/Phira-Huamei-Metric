1. **`chart_io` 的四处修复全部到位，且没有改变 v3 的任何数值**：`engine-v3.json` 重导后
   md5 仍是 `01e70edf35ad19963cdc03f869dd0990`，`node phm-web/tools/golden-engine.mjs` 通过。

## 一、事故与修复：`tools/chart_io.py`

### 1.1 四处修复

| # | 问题 | 现象 | 修法 |
|---|---|---|---|
| 1 | `load_notes_ex` 的 PEC 分支不排序 | `parse_pec` 按**文件行序**返回（按判定线交错），`to_feats` 的 `dt = t_i − t_{i−1}` 出现负值被 clamp 成 0 → 密度窗、running strain、Σdt 全错 | 解析后 `base.sort(key=t)` |
| 2 | `_line_tracks` 不跳过 `null` 图层 | prpr 是 `Vec<Option<_>>`，12 张谱的 `eventLayers` 含 `null` → 整张谱 `AttributeError` 被丢弃 | `if isinstance(el, dict) and el.get(key)` |
| 3 | 缺 `extra=` 参数 | `tools/ab_screen_coords.py` 调 `load_notes_ex(..., extra=True)` 直接 `TypeError` | 追加 4 个屏幕坐标量（见 1.3） |
| 4 | type 映射写反 | 实测 RPE `3 = flick`、`4 = drag`，旧代码是 `{3:D, 4:F}` | `TYPE_MAP = {1:T, 2:H, 3:F, 4:D}`，**同时**改 `build_seq_dataset.to_feats` 的反向表 |

第 4 条必须两边一起改：只改 `chart_io`、不改反向表，flick/drag 的 one-hot 列和 strain 权重
（`k in (0,2)` 给 1.0，其余 0.5）会整体互换。同时改则**逐位等价**（3 仍落在 one-hot 第 3 列），
这也是 v3 md5 不变的原因之一。

另外把 `_track_value` 从「每个音符线性扫一遍整条轨道」改成 `_Track` 预解析 + 二分：

- 语义**逐位保持**：空轨道 → `None`；beat 早于首事件 → `None`；命中分段线性插值；
  `start == end` 返回 `end`；超出末端返回最后一个 `start ≤ beat` 的 `end`；
  事件未按 start 升序（畸形谱）自动退回线性扫描。
- 实测 45015 号谱（9,277 事件）：**1.0 s → 0.27 s**。原文提到的 33 s 是判定线事件更多的极端谱。

## 二、A_extent 256 维进生产

### 2.1 特征与缓存

只取 `docs/结果/片段手型特征-A-B.md` 里唯一值钱的那 8 个指标：

```
bbox_area / diag / span_x / span_y / aspect / path / disp / eff
```

4 种切法（连续 8 / 16 事件、0.5s / 1s 窗）× 8 个统计量（mean/std/min/max/p10/p50/p90/skew）
= **256 维**，追加在 142 维池化之后 → **398 维**。逐维公式、排序、边界条件见 `tools/handshape_spec.md`。

缓存 `data/handshape-extent-v1.npz`（7,504 × 256）：

- 7,492 张复用 `handshape-cache-v1.npz`，抽样 20 张与缓存**逐位一致**（max|Δ| = 0），
  确认 `chart_io` 的修复没有悄悄改动既有特征（`handshape_features` 内部本来就按 (t, x) 重排，
  PEC 的顺序问题在它这里不生效）；
- 12 张原本被填 0 的谱用修复后的 `chart_io` **重算真值**，不再有"假样本"。
  同口径（未裁剪、α=300）复算：canonical 短谱 0.7508 → **0.7532**，即这 12 张真值贡献 +0.0024。

读法：

- **短谱涨、长谱也涨**。这次不存在"牺牲长谱换短谱"的取舍；长谱的 +0.026 在三 seed 里都为正。
- 短谱 ρ 的**跨 seed 方差**从 0.0267（base）/ 0.0215（base_clip）降到 0.0137 —— 与 A/B 报告的结论一致：
  新信息不是"押中了一个好运的切分"。
- 相比 A/B 报告（+0.061，2/3 显著），这次 +0.073 / 3/3 显著，差别来自两处：
  12 张谱的真值（+0.0024）与 z 裁剪（见 2.3）。**裁剪不是刷分手段**，它同时修掉了一个会崩 MAE 的缺陷。

### 2.3 必须裁 z：不加就会出一个"ρ 好、绝对尺度崩"的模型

398 维里有一批**近似常量列**：训练集里几乎全 0，只有极少数谱非零，标准差落在 1e-4 量级
（典型例子 `n8|max|bbox_area`）。这类列标准化后，测试集里一个 0.4 的偏离就变成 z ≈ 4,000，
再乘上岭回归给它的权重，单列就能把预测甩出正常范围：

| 切分 12345（未裁剪） | 短谱 ρ | 短谱 MAE | 短谱预测 sd |
|---|---|---|---|
| base（142 维） | 0.6592 | 0.5287 | 0.710 |
| ext（142+256，未裁剪） | 0.7390 | **0.7440** | **5.206** |

排名还凑合，但绝对尺度已经不可用 —— 而产品最终要的是 b → 定数，不是排名。
把标准化后的 z 裁到 ±8（与序列模型侧同口径）后：

| 切分 | 短谱 ρ 未裁 → 裁剪 | 短谱 MAE 未裁 → 裁剪 |
|---|---|---|
| 20261028 | 0.7532 → **0.7614** | 0.4950 → 0.4874 |
| 12345 | 0.7390 → **0.7486** | 0.7440 → **0.4791** |
| 777 | 0.7653 → **0.7761** | 0.4744 → 0.4659 |

三个切分**全部**是裁剪更好。实现见 `tools/ridge_clip.py`（`clip_z = 8`，`engine-v4.json` 里也写了这个字段）。
注意：这是对**标准化后的特征**裁剪，不是对预测值裁剪；JS 端漏掉这一步会得到"看起来能跑、个别谱离谱"的结果。

### 2.4 序列模型：加手型特征会不会叠加

**做法**：`SeqDiffNet` 的头部原来是 `LayerNorm(64) → Linear(64,1)`；加手型特征后是
`LayerNorm(64) → concat[64, 256] → Linear(320,1)`。256 维先按**训练集**的均值/方差标准化，
再裁 ±8（与岭回归侧同值），**不做**任何谱级池化 —— 它本来就是谱级的。
训练协议、切分、内部验证集、epoch 预算（15）与原来完全一致；参数量 34,306 → 34,562（+0.7%）。

先确认基线没被改动破坏：重跑 142 维序列模型得 `[0.8266, 0.8269, 0.8225]`，与旧结果
`[0.8267, 0.8269, 0.8199]` 前两个 seed **逐位相同**；第三个 seed 差 0.0026，
原因是这次两个训练并行、`--threads 9`（旧的是 14），15 epoch 后 best-epoch 的选择挪了一位。
换句话说：**改动本身不改变原模型的行为**。

**四个模型放同一张表（canonical 切分，测试 1,126；序列模型取 3 seed 的平均预测）**

| 模型 | ρ 短 (n=376) | ρ 全 (n=1,126) | ρ 长 (n=376) |
|---|---|---|---|
| 岭回归 v3（142 维，现役） | 0.7089 | 0.8024 | 0.8202 |
| 岭回归 v4（142+256） | 0.7614 | 0.8319 | 0.8454 |
| 序列模型（20 维事件，现役 seq） | 0.7166 | 0.8328 | 0.8781 |
| **序列模型 + 手型（seq-v2）** | **0.7636** | **0.8511** | **0.8819** |
| 两者都用（等权集成） | **0.7792** | 0.8517 | 0.8772 |

配对 bootstrap（1,000 次，只重采样测试集）：

| 对照 | Δ 短 [95% CI] | Δ 全 | Δ 长 |
|---|---|---|---|
| seq + 手型 **vs seq** | **+0.0467 [+0.0141, +0.0784]** ✅ | +0.0183 [+0.0066, +0.0311] ✅ | +0.0038 [−0.0112, +0.0196] ❌ |
| seq + 手型 **vs 岭回归 v4** | +0.0026 [−0.0334, +0.0363] ❌ | +0.0192 [+0.0065, +0.0323] ✅ | +0.0364 [+0.0149, +0.0612] ✅ |
| 集成 **vs 岭回归 v4** | +0.0177 [+0.0008, +0.0352] ✅ | +0.0198 [+0.0129, +0.0266] ✅ | +0.0318 [+0.0187, +0.0486] ✅ |
| 集成 **vs seq + 手型** | +0.0152 [−0.0042, +0.0338] ❌ | +0.0006 [−0.0057, +0.0067] ❌ | −0.0047 [−0.0152, +0.0054] ❌ |

三 seed 的全量 ρ：seq **0.8254**（sd 0.0025）→ seq+手型 **0.8407**（sd 0.0031）。

**结论：叠加是"部分叠加"，而且只在全/长谱上成立。**

1. **短谱不叠加。** 两条路各自被手型特征抬了 +0.05（岭回归 +0.050 / 序列模型 +0.047），
   然后**收敛到同一个天花板**：0.7614 vs 0.7636，差 +0.0026，CI 跨 0。
   这说明短谱缺的就是"这段摊开多大"这一类几何信息 —— 谁补上都一样，补两次不会更好。
2. **全/长谱能叠加。** 长谱上序列模型本来就强（0.878 vs 岭回归 0.820），
   手型特征对它的增益只有 +0.004（不显著）；但 seq+手型 相比岭回归 v4 仍高 +0.036（显著）。
   两者吃的是**不同**的信息：时间顺序（序列模型）与片段几何（手型）。
3. **集成收益有限。** 等权集成只在短谱 +0.015（不显著），全量 +0.001，长谱 −0.005。
   浏览器端要同时跑两套模型换这点收益，不值。
4. **首选 seq-v2**（短 0.764 / 全 0.851 / 长 0.882）；**轻量替代是岭回归 v4**（398 次乘法，
   短 0.761 / 全 0.832 / 长 0.845，短谱差距 0.002 可忽略）。这也是"两种模型都在短谱撞天花板"
   的直接后果：**短谱的上限不在模型，在特征**。

## 四、限制与已知风险

1. **三个 seed 不是三次独立复现**：共享同一批 7,504 张谱、同样 85/15，测试集高度重叠。
   它们只能排除"某次 permutation 的偶然"，**排除不了"换一批谱就失效"**。
2. **短谱主指标的 CI 下界在 canonical 上只有 +0.0155**：比 A/B 报告（−0.0047）稳，但仍是 1,126 个测试样本的
   量级，别把 +0.05 当成精确值。
3. **`aspect` 在 `sy ≡ 0` 的谱上退化**（PEC 723 张、无 moveY 的 RPE）：`ry + 1.0` 保证不出 inf，
   但语义上等于 `span_x·675`。没有加 `aspect_defined` 标志（那要再开一轮实验）。
4. **缓动只做线性插值**：`sx/sy` 对曲线缓动有偏差；`start == end` 的保持型事件是精确的。
5. **序列模型侧的 z 裁剪（±8）与岭回归侧同值**，但它是在标准化后的输入上做的，两处实现必须一致。
