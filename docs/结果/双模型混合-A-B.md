# 双模型混合 A/B（结构级改进）

> 2026-11-26 · 从 `pde-src` 拆出的第一个**显著有效**的结构级改动
> 结论：**17+ 段显著改善，可上线。**

---

## 一、假设

`pde-src`（`phigros_difficulty_estimator_re`）的真正优势不是模型，是**把任务切窄**：

```
模型 A（主）：1,037 官谱 + 222 高手表 → 稳住中低段
模型 B（专精）：只用 222 张 17+ 高手表 → 专攻顶端
混合：weight = clip((pred - 17.1) / (17.9 - 17.1), 0, 1)
```

它报 17+ MAE 0.39，是「专精模型考专精题」（47 张留出全在 17+）。

**我们的条件更好**：17+ 有 **916 张**，是它高手表（269）的 3.4 倍。

假设：把同样的结构搬到 P.H.M.，17+ 段应显著改善。

---

## 二、方法

| 项 | 做法 |
|---|---|
| 数据 | `data/community.jsonl` 全量，标签清洗到 (1, 20) → **9,504 张** |
| 特征 | 57 维（数值列），`log1p(clip(v,0))`，与 `engine.js` 的 `ridgeBeta` 一致 |
| 模型 | `StandardScaler + Ridge(alpha=3)`，两套同款 |
| 基线 | 单模型（全区间一个 Ridge） |
| 实验 | 主模型（全量）+ 专精模型（标签 ≥ 17.0，916 张）+ 平滑混合 |
| 混合权重 | **按预测值**算，不按标签（推理时没有标签，按标签算等于作弊） |
| 切分 | GroupKFold，按 **charter** 分组（6,818 个谱师，防泄漏） |
| 判据 | 配对 bootstrap 10,000 次，看 ΔMAE 的 95% CI |

**不做带宽搜索**：主结果用预设的 16.5–17.5；其他带宽只作敏感性分析，
而不是「试完挑最好的报」。

---

## 三、主结果（预设参数：混合带 16.5–17.5，5 折）

### 全区间

```
单模型  n=9504  MAE 0.8245  中位 0.4835  p90 1.5204
双模型  n=9504  MAE 0.8204  中位 0.4818  p90 1.5185

ΔMAE -0.0041   95%CI [-0.0060, -0.0022]   更好的占比 100.0%
→ 显著更好
```

### 17+ 子集

```
单模型  n=916   MAE 0.9598  中位 0.7781  p90 1.7573
双模型  n=916   MAE 0.8561  中位 0.6288  p90 1.6354

ΔMAE -0.1037   95%CI [-0.1187, -0.0883]   更好的占比 100.0%
→ 显著更好
```

**中位误差 0.778 → 0.629，改善 19%。**

### 分档

| 定数段 | n | ΔMAE |
|---|---:|---:|
| 1 – 12 | 560 | +0.0180 |
| 12 – 14 | 1,266 | +0.0011 |
| 14 – 15.5 | 3,702 | +0.0005 |
| 15.5 – 17 | 3,060 | +0.0140 |
| **17 – 18** | 619 | **−0.0488** |
| **18 – 21** | 297 | **−0.2181** |

低段（1–12、15.5–17）轻微变差 +0.014~0.018，但整体净收益显著为正。

## 四、稳健性

| 配置 | 全区间 ΔMAE | 17+ ΔMAE | 17+ 中位 |
|---|---|---|---|
| **16.5–17.5（预设）** | **−0.0041** ✓ | **−0.1037** ✓ | 0.778 → 0.629 |
| 10 折 | −0.0036 ✓ | −0.1015 ✓ | 0.775 → 0.635 |
| 带宽 16.0–17.0 | +0.0025（不显著） | **−0.2054** ✓ | 0.778 → **0.481** |
| 带宽 17.0–18.0 | −0.0014 ✓ | −0.0252 ✓ | 0.778 → 0.751 |
| 专精下限 16.5 | −0.0045 ✓ | −0.0388 ✓ | 0.642 → 0.597 |

**方向全部一致：任何参数下 17+ 都显著改善。** 参数只影响幅度。

### 值得注意的一行

带宽 16.0–17.0 把 17+ 中位误差压到 **0.481**，但全区间变成 +0.0025（不显著）——
说明**混合带越宽，专精模型接管越早，顶端改善越大，中段代价也越大**。

这是一个明确的权衡，不是「哪个更好」。上线时选 16.5–17.5（全区间也显著改善），
把 16.0–17.0 留作「追求顶端最优」的备选。

---

## 五、为什么这次是真的（对比 press 特征那次）

| | press 节奏特征 | 双模型混合 |
|---|---|---|
| 性质 | 加特征（同一模型） | 改结构（换分工） |
| 全区间 ΔMAE | +0.0075（不显著） | **−0.0041（显著）** |
| 17+ ΔMAE | +0.0240（更差） | **−0.1037（显著）** |
| 机制 | 被动多一维，被 Ridge 稀释 | 顶端由**专门的模型**负责 |

**加特征的收益会被共线性吃掉；换分工不会。**
这是这次实验最重要的方法论收获。

## 六、上线路径（未实施）

要真正上线，需要：

1. **重训并导出两套权重**
   - `W_main`：全量训练
   - `W_top`：只取标签 ≥ 17.0 的样本训练
   - 两套都走 `fit_v2.py` 的现有格式（dims / mu / sd / w / ym）

2. **改 `engine.js` 的 `reportFromChart`**
   - 新增 `ridgeBeta(f, W_top)`
   - `weight = clip((p_main - 16.5) / (17.5 - 16.5), 0, 1)`
   - `point = (1-w)*p_main + w*p_top`
   - ⚠ `engine.js` 已 899 行（上限 900），**必须先把这段逻辑拆成独立模块**

3. **升 `ENGINE_VER`**（`com-ridge37-v1.1.0` → 新版本），并重跑
   `golden-engine.mjs` 金标、`audit-baselines.mjs`

4. **同步 `ref-official.js` / `ref-com.json`**（若定数缓存需重算）

**风险**：这是引擎级改动，改完所有缓存都要重算，且金标必须重建。
不是「改一行」，是一次正式的版本升级。
