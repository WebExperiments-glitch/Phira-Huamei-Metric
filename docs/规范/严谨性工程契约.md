## 零点五、beat 换算：从源码逐字确认（最高风险项已闭环）

竞品 `phigros_difficulty_estimator` 漏了 `b` 项，导致 280BPM 谱时长少算 131 秒、定数偏差 0.56。
**这是整个项目最容易错、错了最难发现的地方。** 已从 Phira 源码逐字比对确认。

**官方实现（`prpr/src/core.rs`）：**

```rust
/// `(i, n, d)`: `i + n / d`     ← 官方注释原文
pub struct Triple(i32, u32, u32);

impl Triple {
    pub fn beats(&self) -> f64 {
        self.0 as f64 + self.1 as f64 / self.2 as f64    // ← a + b/c
    }
}

impl BpmList {
    pub fn time(&mut self, triple: &Triple) -> f64 { self.time_beats(triple.beats()) }

    pub fn time_beats(&mut self, beats: f64) -> f64 {
        time + (beats - start_beats) * (60. / bpm)
    }
}
```

**正确公式（已确认，无歧义）：**

```
beats   = a + b / c                       ← 不是 a/c
seconds = 累计时间 + (beats − 段起点beat) × (60 / bpm)
```

`bpmfactor` 位于 `eventLayers` 的变速事件，**全量 8,815 张统计为 1.0（无一例外）**，
故实际退化为 `seconds = 60 / BPM × beat`。

**Rust 侧实现要求：**

- `Triple` 用整数三元组解析，**禁止用 f64 直接读 JSON**（避免精度损失）
- 必须实现 `BpmList` 的**逐段累计**，不能假设全谱单 BPM（11.0% 的谱是多段）
- 除法前必须判 `c != 0` 与 `bpm > 0`（审计已确认全量无异常，代码仍须防御）

**验证方式**：单 BPM 谱用 `max(endTime) × 60/BPM` 反推总时长，必须落在 5s~30min。
审计脚本已内置此检查，全量通过。

#### 审计抓到的两个真实问题

**问题 1：审计脚本自身的 bug（已修）**

初次运行报「405 处音符类型和不守恒」。排查发现是**审计脚本分类时未先剔除 `isFake` 音符**，而 manifest 记录的 1,202 是正确的。

→ 这条恰恰证明了门禁的价值：**如果没有逐条核对原始文件，405 处「不一致」会被误当成数据问题去"修"，反而污染正确数据。**

**问题 2：负数 beat 的判据过严（已修）**

谱 69556《ここから、ここから》`startTime = [-1, 0, 1]`（beat = −1.0，RPE 160，bpm=175）。

查 Phira 源码 `BpmList::new`：
```rust
for (now_beats, bpm) in ranges {
    if let Some(bpm) = last_bpm {
        time += (now_beats - last_beats) * (60. / bpm);
    }
    ...
}
```

**官方完全不检查负值** —— 负值会算出负时间，但不会崩溃。故这是**可接受的数据特征**，判据从 FAIL 降为 WARN。

→ 教训：**判据必须对齐上游真实行为，不能凭直觉设定。** 否则门禁会误报，久而久之就会被绕过。

## 二、结论层：样本量契约

### 2.1 已犯的错误（引以为戒）

**2026-10-04 的教训**：基于 2,024 张样本得出结论，全量 8,646 张复核时**两处翻转**。

| 结论 | n=1,978 | n=8,646 | 性质 |
|---|---|---|---|
| Drag% 偏相关 | −0.083「谱型混淆」 | **−0.135「真实效应」** | **方向性质翻转** |
| BPM 偏相关 | +0.049「无判别力」 | **+0.119「真实效应」** | **有无翻转** |
| 物量 r | +0.376 | +0.258 | 强度腰斩 |

**根因**：小样本下弱相关的方向不可靠。且**谱型混淆与真实效应必须靠偏相关区分，而偏相关需要足够样本量才能稳定。**

### 2.2 强制规则

| 用途 | 样本量下限 | 判据 |
|---|---|---|
| 描述性统计（均值/分布） | 500 | 足够 |
| 相关性方向判断 | **2,000** | 低于此值只作参考，不下结论 |
| 偏相关（区分混淆） | **5,000** | 低于此值不得下「真实效应/谱型混淆」判断 |
| 模型权重标定 | **8,000** | 低于此值只用官谱，不用社区谱 |

**当前语料 8,815 张，全部达标的只有偏相关和权重标定。**

### 2.3 稳定性验证要求

任何「X 影响 Y」的结论，必须报告**分组稳定性**：

- 按定数分档（低/中/高）分别计算，看方向是否一致
- 按物量分档分别计算，看方向是否一致
- 若方向在任一分档内翻转 → 结论不成立，必须降级为「假设」

## 三、方法层：分析纪律

### 3.1 相关性 ≠ 因果

- 所有 r 值只说明「相关」，不说明「驱动」
- 报告必须用「观测到 X 与 Y 相关」，禁止用「X 导致 Y」
- 权重方向若来自相关分析，必须标注「**假设，待回归验证**」

### 3.2 必须算偏相关

**只要特征之间存在混淆可能，就必须同时报告原始相关与偏相关。**

正例：Drag% 与定数负相关 −0.162 看着显著，但控制物量后降到 −0.135 —— 说明物量贡献了相当一部分。反过来，Tap% 控制物量后**上升**（+0.197 → +0.217），是真效应。

### 3.3 必须画分档表

相关系数只看方向，非线性一律看不见。**每个特征必须给五分位表。**

已发现的非线性：
- Drag% > 20% → 断崖（15.06 → 13.27）
- Tap% > 60% → 饱和（+0.01）
- Flick% > 76% → 崩塌（15.05 → 11.64）
- **物量在定数 12–13 档有反常凹陷**（中位 579 < 0–10 档的 657）

**结论：模型必须用分段函数，不能线性。**

### 3.4 无效特征要明确剔除

**假键率 r = −0.0066（偏相关后）→ 完全无关。**

必须写进「不进模型的特征」清单，而不是留着占一个权重。很多工具会把假键计入密度从而虚高——这个错误已被数据排除。

### 3.5 物性校验

任何解析器必须通过：

- 音符类型占比之和 = 100%
- `startTime` 三元组格式合法
- BPM 严格大于 0（防除零）
- 空谱、无 BPM 谱有显式处理路径

## 五、诚实性契约

### 5.1 报告必须包含「模型不知道什么」

固定章节，不可省略：

- 哪些特征权重低（说明判定不了）
- 置信度区间
- **所有已知会误判的谱型**
- 训练/校准数据未覆盖的情形

竞品自陈四个坑（耐力型高估 +1、19.1 档欠定价 −0.4、表演型虚高、低定数段噪声大）**必须预先声明，而不是等别人发现**。

### 5.2 定位声明不可弱化

❌ 「复现 Phigros 官方定级标准」——它不存在
❌ 「官方定数规则」——社区观测，非官方发布
✅ 「用可审计的公开规则提供客观难度参考与合规检查」

**任何对外文案都不得夸大为「规则制定者」。** 社区不赋予强制力，我们只保证可复现。

### 5.3 区分「观测事实」与「推断」

| 类别 | 标注方式 |
|---|---|
| 查证到的事实 | 附来源链接 |
| 数据观测 | 附复现命令 + 样本量 |
| 推断/假设 | **明确标注「假设」** |
| 未找到 | **明确写「未找到」** |
