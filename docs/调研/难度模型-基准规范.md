# PHM-Bench v1 · 谱面难度预测基准规范

> 2026-11-01。参考当代 LLM 评测的做法（LiveBench 的防污染、HELM 的分场景、
> Arena 的两两比较），为「谱面难度预测」设计一套能公开比较、能防作弊、
> 且结论不会被单个数字误导的基准。
>
> **本规范的目的是：让外部模型可以公平地和我们的模型比较，
> 而我们的最优模型不开源。** 基准是公开接口，权重不是。

---

## 0. 为什么不能只用「随机切分 + ρ」

一个数字会被四种方式骗过，每一条都有实例：

| 失败模式 | 表现 | 实例 |
|---|---|---|
| **谱师泄漏** | 同一作者同时出现在训练与测试，模型背的是风格 | 随机切分下无法察觉 |
| **时间泄漏** | 用新谱训练去预测旧谱，而产品里永远是预测新谱 | — |
| **捷径学习** | 只学会「音符多就是难」 | 实测：**单变量物量回归 ρ 0.495** |
| **长尾崩溃** | 总榜好看，长谱短谱全废 | 实测：长谱 0.642 / 短谱 0.587 |

所以基准的第一原则：**分项必须拆开，总分必须宏平均。**

## 1. 任务集（T1–T8）

每一组都是一次独立评测，**不做加权**，最终总分为八项的宏平均。

| 编号 | 任务 | 切分方式 | 考什么 |
|---|---|---|---|
| **T1** | 随机 | 85/15 随机 | 基准线，与历史数字可比 |
| **T2** | 换谱师 | 按 `uploader` 分组，15% 的**作者整组**留出 | 能否泛化到没见过的作者 |
| **T3** | 时间外推 | 按 `created` 排序，最新 15% 作测试 | 能否预测**新谱**（真实场景） |
| **T4** | 冷启动 | 训练用 ≥200 人的谱，测试用 **50–99 人** | 真实新谱形态：有人玩但不多 |
| **T5** | 长谱 | 测试 = 事件数 top 10% | 上下文与长程建模 |
| **T6** | 短谱 | 测试 = 事件数 bottom 10% | 信息稀薄时的判断 |
| **T7** | 截断鲁棒 | 测试谱只给**前 50%** 事件 | 信息不全时是否还能给合理值 |
| **T8** | 跨格式 | 测试 = 全部 PEC 格式谱面 | 不能只对 RPE 调过参 |

### 防污染（关键）

三条同时做，缺一不可：

1. **隐藏测试集**：从 T1–T8 的测试部分里再抽 40%，**永不公开谱面 id**，
   只公开 `sha256(排序后的 id 列表)` 作为承诺。外部提交模型，我们代跑。
2. **公开 dev 集**：剩下的 60% 公开，供人自行迭代。公开集成绩**不计入榜单**。
3. **滚动更新**：每季度把 T3 中「上传日期晚于上次发布」的谱面并入隐藏集
   （LiveBench 的做法：只用发布后的新数据）。这保证任何在旧数据上训练过的模型
   都会在新区间上露馅。

> 承诺文件：`data/bench/hidden.sha256`。任何人可以用公开的 id 清单验证
> 隐藏集不是事后挑的。

## 2. 指标

### 2.1 主指标

| 指标 | 定义 | 为什么是它 |
|---|---|---|
| **ρ（Spearman）** | 预测与实测难度 b 的秩相关 | 排序才是我们提供的新信息；绝对值有官方标称兜底 |
| **宏平均 ρ** | 八项任务的 ρ 的算术平均 | 防止「随机切分刷分」 |
| **±0.5 档准确率** | 误差 ≤0.5 级的比例 | 产品真正需要的粒度 |
| **bias** | 平均（预测−真值） | 抓系统性高估/低估 |

### 2.2 辅助指标（必须一起报）

```
τ (Kendall) · MAE · RMSE · R² · ±1 档准确率
成本：参数量 · 单谱推理延迟（CPU，中位数）
```

成本必须报 —— 一个 4.6M 参数的模型和一个 50 参数的线性模型跑出同样的 ρ，
它们的价值完全不同。参照 LiveBench 的「每条成功任务的成本」列。

### 2.3 必须给置信区间

n=1,018 时 ρ 的标准误约 **0.031**。也就是说 **0.03 以内的差距是噪声**。
所以：

- 每个数字都带 **95% bootstrap CI**（重采样 2,000 次）
- 两个模型比较用**配对 bootstrap**（同一批样本上重采样误差差值的分布）
- 明确标注「无法区分」：CI 跨 0 就是平手，不许写成「领先」

## 3. 两两比较（Arena 式）

除了绝对指标，加一个**胜率矩阵**——它比 MAE 更抗离群值：

```
对每一张测试谱：误差更小的模型赢
聚合全部谱面 → Bradley-Terry 拟合出 Elo
```

与人类投票的 Arena 不同，这里的「谁更好」是**客观可算的**（谁更接近实测 b），
所以不存在偏好噪声，只存在抽样噪声 —— 用 bootstrap 给 Elo 差值的 CI。

**判读**：Elo 差 <20 视为同级（沿用 Arena 的经验阈值）。

## 4. 天花板

榜单必须显示上限，否则会有人以为 0.9 可达：

```
实测 b  vs  谱师标称       ρ = 0.68
```

两个独立测量之间只有 0.68 一致 —— **难度本身有约 0.3 的不可约分歧**。
所以：

- ρ ≈ 0.75 已经接近可用上限
- 任何宣称 ρ > 0.85 的结果，先怀疑泄漏

## 5. 提交协议（防作弊）

| 规则 | 原因 |
|---|---|
| 只接受**代码**，不接受预测文件 | 防止在公开集上手工调参 |
| 推理必须**确定性**（无随机采样；若有，固定种子跑 3 次取中位） | 防止多次采样挑最好 |
| 单谱推理**不得访问网络** | 防止偷查 Phira 上的玩家成绩 |
| 输入只给**谱面事件流**，不给谱面 id、作者、上传时间 | 防止直接查表 |
| 必须报**参数量与延迟** | 成本是一等信息 |
| 同一机构**最多提交 3 个** | 防止选择性发布（挑最好的那个报） |

最后两条来自当代评测的两个已知失败模式：**格式调优**与**选择性发布**。

## 6. 榜单格式

```
名次  模型              宏平均ρ   T1    T2    T3    T4    T5    T6    T7    T8   参数  延迟
 1    P.H.M. (闭源)     0.7?     ...   ...   ...   ...   ...   ...   ...   ...  —     —
 2    SSM (开源)         0.7?     ...
 3    49维岭回归（基线）  0.7?     ...
 —    只数音符（下界）    0.49     ...        ← 永远显示，用来羞辱无效模型
```

规则：

- **每项都带 CI**，表格里只放点估计，点开看区间
- **恒显示两个锚点**：只数音符（下界）与天花板 0.68（b vs 标称）
- 闭源模型只报成绩不报权重，但**必须报参数量与延迟**

---

## 7. 与「开源/闭源」策略的关系

```
开源：SSM（0.7549）· 岭回归基线 · 数据流水线 · 本基准
闭源：我们最好的那个模型
```

基准的作用是**让闭源部分可被验证**：别人不能看权重，但能看它在八个任务上的成绩，
并且能用自己的模型在同一套隐藏集上挑战。这比「不公开任何东西」可信，
也比「全开源」更能形成积累。

⚠ 前提是**基准本身要经得起质疑**：隐藏集承诺、确定性推理、配对检验、
成本披露 —— 这四条缺一条，榜单就只是自说自话。
