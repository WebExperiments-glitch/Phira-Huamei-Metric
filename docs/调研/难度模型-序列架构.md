# 难度预测的序列架构：从 LNN 到选择性状态空间

> 2026-11-01。回答一个问题：**给定 6,916 张谱面的事件流，什么样的架构才配得上这份数据？**
> 结论先行：**纯液态网络（LTC/CfC）方向对、实现错** —— 它的时间感知正是我们要的，
> 但逐步递推在训练时无法并行，会让我们把时间全花在等 Python for 循环上。
> 正确形态是**把 Δt 放进离散化步长、再用分块扫描并行化**，也就是选择性状态空间（S6 / Mamba 的核心机制）。

---

## 1. 数据长什么样（这决定了架构）

```
样本数     6,916 张（有 b 标签，≥50 名玩家）
序列长度   中位 1,254 个事件 · p90 4,087 · 最长约 10,000
时间间隔   0.01 ~ 3 秒不等距，均匀分布
每事件     10 维（dt、log dt、x、类型 one-hot、hold、above…）
标签       每张谱一个标量 b（玩家实测难度）
```

三个性质合起来是**非典型**的：

1. 间隔不等距，而且**间隔本身就是难度信号**（密集段难）。
2. 长度方差极大（10 倍以上），padding 必须廉价。
3. 样本相对序列长度**极少**（6.9k 样本 × 平均 1,254 步）。

---

## 2. 文献对照（2026-11 现状）

| 架构 | 时间处理 | 训练并行度 | 小数据表现 | 本机可用 |
|---|---|---|---|---|
| **Transformer**（现有基线的一层注意力） | 位置编码，时间靠特征 | O(L²)，快 | 一般 | ✅ |
| **LTC / CfC**（Hasani, AAAI 2021 / Nature MI 2022） | **τ(x,h) 连续时间**，天然吃 Δt | ❌ **逐步递推，无并行** | 论文主打小样本 | ✅ 但要 Python 循环 |
| **Mamba / S6**（Gu & Dao, 2023） | **Δ_t = softplus(Linear(x_t))**，输入依赖的离散化步长 | ✅ 关联扫描 O(log L) | 未在大规模验证 | ⚠️ 官方 kernel 要 CUDA |
| **LrcSSM**（2025） | 液态电阻电容 + 对角 Jacobian | ✅ 关联扫描 | UEA 均值 66.3%（Mamba 58.6） | ⚠️ 无现成实现 |
| **Hyena** | 长卷积 + 门控 | O(L log L) | — | ✅ |

### 关键的等价性

Mamba 的离散化是 `Ā = exp(Δ·A)`，而 Δ 由输入决定。把它和 CfC 的更新并排看：

```
CfC:      h ← h·e^(-dt/τ(x,h)) + (1-e^(-dt/τ(x,h)))·f(x,h)
S6:       h ← h·exp(Δ(x)·A)    + (1-exp(Δ(x)·A))·(Δ(x)·B(x))·x
```

**同一个东西**：都在用「输入决定的时间常数」控制状态衰减。
差别只在 **A 是学出来的对角常量（S6）还是网络（CfC）** —— 而 S6 的常量选择换来的是**可并行**。

⇒ 我们要的「吃真实 Δt」在 S6 里是原生能力，不是要额外改造的东西。**把特征里的 dt 换成 Δ 的输入即可**。

### 为什么不用 LNN 的原始实现

一篇 2026 年的工程记录（TEMPORAL-1）说得很直白：他们把 LNN **串在 Mamba 之后**当修正层，
而不是当完整的序列 ODE —— 理由是"完整 ODE 会重复 Mamba 已完成的工作，代价高收益低"。
这和我们的判断一致：纯 CfC 的逐步递推会把 `1,254 步 × batch` 变成 Python 循环，训练时间不可接受。

## 3. 怎样压缩时间（两个层面，分开说）

用户问的"压缩时间"有两个意思，这里分别处理。

### 3.1 训练墙钟时间：分块扫描

朴素实现是 `for t in range(L)`，L=1,254 时一次前向就有 1,254 次 Python 迭代。
关联扫描能把它降到 O(log L)，但**完整并行扫描在 CPU 上要物化 (B, L, D, N) 中间量**，
1,254 × 64 × 16 × 4 字节 × batch 32 = 164 MB —— 能跑，但数值上 `exp(Δ·A)` 连乘 1,254 次会下溢。

**分块扫描（chunked scan）**是工程折中：

```
把 L 切成 C=64 的块 → 块内做 64 步顺序（状态小、数值稳）→ 块间只传一次状态
顺序深度：1,254 / 64 ≈ 20 步   （而不是 1,254 步）
```

在纯 PyTorch 上这就是 20 次循环，**比朴素实现快 60 倍**，且不需要 CUDA kernel。

### 3.2 序列长度压缩：把 4 个事件并成 1 组，但**保留真实时长**

现有基线已经有一个 `Conv1d(stride=4)` 的 stem（4 事件 → 1 位）。问题在于它把
4 个事件当成"等距的 4 个 token"来卷，**组的实际时长（0.05 秒还是 0.8 秒）从特征里消失了**。

改法：分组时把组内 dt **求和**，作为该组的 Δ 输入：

```
组 g 的时间跨度 = Σ dt_i（i ∈ g）   ← 这才是这一"步"在连续时间里走了多久
```

这样长度掉到 1/4（L≈313），而时间信息不但没丢，反而从"逐事件"变成了"逐组的真实步长"。
**长度压缩与时间保真在这里不冲突** —— 因为 SSM 的 Δ 本来就是任意的正实数。

## 4. 迭代路线（每步都要能独立判读）

基线已经存在：`tools/train_seq.py`，Conv1d(stride4) + 膨胀卷积群 + 1 层注意力，79k 参数，**ρ 0.7506**。

| 版本 | 改动 | 参数量 | 训练成本 | 判据 |
|---|---|---|---|---|
| v0 | 基线（已有） | 79k | 30 min | 0.7506 |
| **v1** | 把卷积主干换成**单层选择性 SSM**，Δ 来自组内 Σdt；分块扫描 C=64 | ~80k | ~40 min | > 0.7506 才算有价值 |
| v2 | **双向** SSM（正序 + 反序，拼接）—— 难度取决于全局结构，单向只看得见"过去" | ~120k | ~60 min | v1 若接近但未超，双向通常 +0.01~0.03 |
| v3 | 两层 SSM + 残差 + 门控（Mamba block 的最小形） | ~200k | ~90 min | 看是否还在涨 |
| v4 | 时间分箱（固定 100 ms 帧）替代事件分组 | ~80k | ~40 min | 与 v1 对照，判断"事件序" vs "时间栅格"哪个更合适 |

**判据红线**：49 维 ridge（纯线性）就是 **0.752**。任何复杂架构若到不了这条线，
说明复杂度没有换来信息，该退回去。

## 5. 风险与反面证据（写下来，免得自我安慰）

1. **线性模型已经 0.752。** 这是最强的反面证据：如果 49 个手算特征的线性组合就能到 0.752，
   那"更会读序列"未必能超过它 —— 因为手算特征里已经含了密度、位移、类型分布等摘要。
2. **0.6B LLM 读原始序列只有 0.598**（固定算力学习曲线，见 `docs/调研/难度模型实验记录.md`）。
   这说明原始序列的**表示**对模型不友好，而不完全是信息不足。
   更换架构（而非放大模型）是对的方向，但不能保证突破 0.75。
3. **数据只有 6,916 张。** 任何参数量超过 ~50 万的模型都需要强正则，否则先过拟合。
   所以 v1–v3 的参数量刻意压在 80k–200k。
