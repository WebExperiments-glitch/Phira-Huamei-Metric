# 逐音符成绩采集规范 v1

> 2026-11-16。目的不是"多收数据"，是**收能用的数据**。
> 判断标准只有一句：一条成绩能不能同时回答"这张谱多难"和"这个人多强"。
>
> 当前 52 条实测诊断见 [成绩数据-基线诊断.md](./成绩数据-基线诊断.md)。

---

## 0. 先说清成败由什么决定

**"表现→难度"这层能不能做成，不由模型决定，由样本结构决定。**

要从一个玩家的表现反推谱面难度，必须能把两件事分开：

```
观察到的 acc = 玩家水平 + 谱面难度 + 噪声
```

只有三类样本能分离它们，其余都是废样本：

| 结构 | 分离原理 | 当前有没有 |
|---|---|---|
| 同一人 × 同一谱 × 多局 | 玩家与谱都固定，多局的方差 = 噪声下界 | ✅ 12 张谱有 ≥2 局 |
| 同一人 × 多张谱 | 玩家固定，谱间 acc 差 = 难度差 | ✅ 15 张谱 |
| **多人 × 同一谱** | 谱固定，人间 acc 差 = 水平差 | ❌ **52 条全匿名，0 个玩家身份** |

**现状纠正（2026-11-16）：52 条全是同一个人（本人）打出，47/47 同一个城市。**
所以第三类不是"缺身份"，是"缺人"——`owner_id` 全 null 只是表象，补账号也没用。
单玩家下"玩家水平"是常数，可做"这个人视角的难度排序"，泛化不到群体。

**这决定了规范的重心**：身份/位置这类"补字段"的动作优先级下调（见 P1/P2 修订），
真正决定成败的是把**谱内多局**做厚（P0）和**让更多人打**（产品分发，非客户端技术问题）。

## 1. 采什么：优先级从高到低

### P0 — 同谱多局（现在就能做，最有价值）

- **目标**：每张目标谱累计 ≥5 局有效局，其中至少 2 个不同玩家（见 P1）。
- **为什么**：谱内噪声实测 SD=0.0104，谱间差异 SD=0.0192，信噪比只有 **1.85**。
  多局取均值能直接压噪声——这是唯一不依赖任何模型就能提升信号质量的手段。
- **怎么打**：同一张连打 5 遍，中间不要换谱。acc 会自然波动，波动本身就是信息。

### P1 — 玩家身份（降级：单人现状下不是瓶颈）

- **现状**：52 条全是本人打出，`owner_id` 全 null。客户端只有 Phira 账号、没有 huamei 账号，
  匿名上报是 2026-11-15 有意开的（数据比身份稀缺）。
- **判定**：**补身份解决不了当前问题**——人只有一个，玩家水平是常数。
  匿名样本照收不误，分析时按 `owner_id is null` 分层即可。
- **要求**：带 `x-phira-token` 仍要做（`phiraFallback` 验上游 `/me`），但目的是**未来多人采样时**
  能区分玩家，不是为了让这批数据能建模。别为这件事改链路。

### P2 — 谱面特征连接（断链，需补）

- **现状**：52 条里只有 **5 条**能在 `phm_charts` 里匹配到谱面特征，其余 47 条连不上。
- **后果**：`difficulty` / `ref_const` / `nps` / `ps_score` 这些官方与引擎标签全部缺席，
  无法做"人类表现 vs 官方定数"的对照（这是检验偏差的基准）。
- **要求**：打之前先确认该谱已在 `phm_charts`。未收录的谱先走一次贡献/分析流程再打。
- **这是当前少数"改采样动作就能补"的缺口**，优先级因此从 P2 提到与 P0 并列。

### P3 — 弃疗局标注（不需要改代码）

- **现状**：6/52 条 acc <0.5（app 在结算中断连或玩家中途放弃），判定项之和仍等于物量，
  是真打完的，不是脏数据。
- **处理**：分析时统一按 `accuracy >= 0.5` 过滤，不要删库。规范口径固定在 tools 里。

## 2. 怎么打：一次标准采集的流程

```
1. 选谱：从 data/vote-priority.json 的高优先争议谱里挑（那里最需要人类信号）
         → 确认 chart_id 已在 phm_charts（P2）
2. 连打：同一张谱连续打 5 局，不换谱、不改速度、不改判定设置
3. 身份：登录 Phira 账号再打（让 x-phira-token 带上），无法登录就照打，按匿名存
4. 检查：打完跑 node tools/hm-stats.mjs --verbose，看这 5 局有没有进来
5. 复查：隔 1~2 天重跑 tools/audit / 基线诊断，确认 chart_digest 一致（同谱版本没变）
```

**不要做的事**：

- ❌ 不要一张谱只打一局就换——那只能进"覆盖度"，进不了"信噪比"
- ❌ 不要中途改速度/判定设置——不同设置的表现不能放进同一组比较
- ❌ 不要把 acc<0.5 的弃疗局算进均值——会污染（实测 27997 的 acc 从 0 到 0.984，全靠弃疗局拉低）

## 3. 字段检查清单（打完对一遍）

| 字段 | 当前完整率 | 要求 | 说明 |
|---|---|---|---|
| 判定四项之和 = 物量 | 100% | 必须 | 硬约束，服务端已守 |
| `played_at` | 100% | 必须 | 结算时刻 |
| `chart_digest` | 96.2% | 必须 | **同谱多局的前提**——digest 不同说明谱面版本变了，不能放一起比 |
| `max_touch_points` | 94.2% | 尽量 | 键盘填 0 ≠ null，语义不同 |
| `device` | 90.4% | 尽量 | 机型/定位 |
| `touch_heat` | 90.4% | 尽量 | 8×8 落点图，可反推手型 |
| `judge_blob` | 100% | 必须 | 逐音符判定，最稀缺的信号（见下） |
| `gyro` | 44.2% | 有则更好 | beta.31+ 全采到，旧版本没有是版本问题不是 bug |

### judge_blob 是被低估的资产

52 条全部有逐音符判定（v2 格式：1 字节版本号 + 每 8 字节一条判定）。
基线诊断已能从里面解出"每张谱哪些音符被反复打空"——这是**直接指向难点位置的信号**，
比整曲平均 acc 细得多。规范上要保证它一直随成绩上传（客户端已做，勿关）。

## 4. 数据到什么程度可以开始建模

| 门槛 | 当前 | 达成后能做什么 |
|---|---|---|
| 有效局 ≥ 200（现 46） | ❌ | 任何相关系数的标准误才降到可接受（n≈1000 时 SE≈0.031） |
| 同谱 ≥5 局的谱 ≥ 20 张（现 0~1） | ❌ | 多局均值压噪声，信噪比从 1.85 往上提 |
| 带身份的谱 ≥ 50 条 | ❌ | 才能估计"玩家水平"项，做双人对比 |
| 谱面特征匹配率 > 80%（现 9.6%） | ❌ | 才能对照官方定数，检验偏差 |

**这四条没达成之前，任何"表现→难度"模型的 ρ 都不许写进结论。**
现在的正确动作是按第 2 节连打采样，不是换模型。

## 5. 口径纪律（防止自己骗自己）

- 任何相关/提升必须给 **95% bootstrap CI** + 样本量 n；CI 跨 0 写"无显著差异"。
- 比较两个模型用**配对 bootstrap**，不比点估计。
- "同谱多局"以 `chart_digest` 一致为准，不以 `chart_id` 为准。
- 弃疗局过滤口径固定在工具里，不许每次临时改（昨天说 100% 今天说 98% 就是口径漂移）。
