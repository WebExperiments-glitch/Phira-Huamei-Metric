# 降门槛：按 UID 采集成绩的可行性

> 2026-11-18 · 起因：技术链条太长（电脑 + iPad + 签名 + 开发者模式 + GitHub + 加速器），
> 普通人无法贡献成绩，导致样本永远只有一个人。
> 本文验证一条替代路径：**不问玩家要安装包，只要一个 Phira UID**。

---

## 结论先行

| 问题 | 答案 |
|---|---|
| 只凭 UID 能拉到成绩吗？ | ✅ **能**，官方 API 公开，无需登录、无需客户端 |
| 玩家要做什么？ | 在网页填一个数字 UID，点提交。**其余零操作** |
| 能拿到哪些字段？ | `chart, score, accuracy, perfect, good, bad, miss, speed, max_combo, mods, full_combo, time` |
| 这些字段够做难度分析吗？ | ✅ 够——难度模型只需 chart_id + acc（+ 定数） |
| 拉得到全量吗？ | ❌ **不行，硬上限 20 条**（`limit=100` 无效） |
| 能替代本地 fork 上报吗？ | ❌ 不能。你的账号 584 条，API 只给 20 条（3.4%） |

**一句话**：这条路能大幅降低第一道门槛（让路人愿意参与），但**不能解决统计效力**——
每人 20 条、能对上定数的只有 11 条，n=11 做不出任何显著结论。

---

## 实测证据

### 端点

```
GET https://phira.5wyxi.com/record?player={uid}
```

- 无需 `Authorization`（对比 `/record/best/{id}` 返回 401 UNAUTHENTICATED）
- 返回最近 20 条成绩，按时间倒序
- `limit=100&offset=N` **无效**，始终 20 条；翻页拿不到更多

### 字段（样本）

```json
{
  "id": 222267807, "player": 2771878, "chart": 80030,
  "score": 924279, "accuracy": 0.9839339,
  "perfect": 654, "bad": 1, "miss": 9,
  "speed": 1.0, "max_combo": 580,
  "best": true, "best_std": true, "mods": 0,
  "full_combo": false, "time": "2026-11-18T12:10:55.691509Z"
}
```

### 覆盖率（用 UID 2771878 实测）

| 指标 | 值 |
|---|---|
| API 返回 | 20 条 |
| score ≥ 70 万 | 19 条 |
| 能对上我们定数 | **11 条**（涉及 9 张谱） |
| 账号实际成绩数 | 584 条（`user/{uid}/stats`） |
| 覆盖率 | 20 / 584 = **3.4%** |

## 这对「需要第二个玩家」意味着什么

上一轮的结论是：单人数据在数学上无法分离「难度」与「能力」，必须有第二个人打同一张谱。

按 UID 采集能做到的：
- ✅ 让**第二个人、第十个人**零成本参与——只要他们愿意给一个 UID
- ✅ 每人贡献约 11 条可配对成绩，且是**别人打过的谱**，正好打破单人退化
- ✅ 不需要他们装任何东西，不需要懂 GitHub / 加速器 / 签名

做不到的：
- ❌ 每人 11 条数据量太小，单个玩家的 r 估计极不稳
- ❌ 只有最近 20 条，拿不到历史最好成绩
- ❌ 取决于玩家最近打的是不是我们有定数的谱（这次是 11/19）

**但有统计学意义的是「人数 × 11 条」，不是单人的 11 条。**
100 个玩家 → 约 1,100 条配对成绩 → 接近项目规矩里 n≈1000 的量级。
这才是这条路真正的价值：**用人数换样本量**。

---

## 两个必须注意的坑

1. **公开成绩 ≠ 授权。** 端点公开不代表可以随意采集和使用他人数据。
   上线前需要：明确告知用途、让用户主动提交 UID（视为同意）、
   只存 `chart_id / acc / score` 这类最小字段，不存身份信息、
   提供删除机制。隐私政策要同步更新。
2. **重复谱要按玩家取最佳。** 20 条里同一张谱可能多条（这次 80030 和 83917 各 2 条），
   直接全用会给热门谱过高权重。按 `player + chart_id` 取 `max(accuracy)`，
   与本地 `hm_plays` 的聚合口径保持一致。

---

## 建议的落地形态

网页新增一个入口「贡献成绩」：

```
[ 输入 Phira UID ] [提交]
   ↓ 服务端调 /record?player={uid}
   ↓ 过滤 score>=700000、按 chart 取最佳 acc
   ↓ 只写 chart_id / accuracy / score / 玩家哈希（不写 UID 原文）
   ↓ 返回「你贡献了 11 条成绩，涉及 9 张谱」
```

**用户端成本：一个数字，一次点击。**
这才是能把第二个人拉进来的门槛。
