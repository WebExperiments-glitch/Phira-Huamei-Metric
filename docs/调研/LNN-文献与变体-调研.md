## 二、LNN 声称的优势（有出处）

1. **不规则采样**：状态演化直接吃 `dt`，不需要先把时间轴规则化
2. **OOD 鲁棒**：连续时间滤波对噪声与分布漂移更稳
3. **参数效率**：同等任务下 1–3 个数量级更少参数
4. **推理时可适应**：不改权重，靠隐状态轨迹适应扰动

**关键一句（ScienceDirect 2026 综述）**：

> Liquid models should be evaluated where **irregular sensing, elapsed time, recurrent state evolution, and embedded execution** are central.

—— **这四条，我们的场景全中**：dt 极不规则、时间尺度重要、CPU 部署、序列短。

## 三、⚠ 最重要的反面证据：Liquid AI 自己淘汰了液体算子

LFM2（arXiv:2511.23404）用的是**硬件在环架构搜索**：每个候选都编译到
llama.cpp / ExecuTorch，在 Galaxy S24 Ultra 和 Ryzen HX 370 上实测
TTFT、decode 延迟与峰值内存，**再**评价质量。

搜索结果：

```
被淘汰：Mamba、S4、Mamba-2、线性注意力变体、混合 SSM、
        以及 Liquid-S4（他们自家的液体状态空间）
活下来：门控短卷积（16 层里 10 层）+ GQA 注意力（16 层里 6 层）
```

**发明 LNN 的公司，在自己的量产模型里没有用液体算子。**

原因（他们自己说的）：纸上推出来的复杂度优势，落到真实硬件上不一定兑现。

这条对我们的意义极重——**我们纠结的“要不要换 LNN”，
恰好是人家用一整个架构搜索团队、在真机上量完之后否掉的选项。**

## 四、已知缺陷（文献层面）

- **求解器依赖**：原版 LTC 需要 ODE 求解器，长序列上开销大（CfC/GCU 缓解）
- **τ 初始化敏感**：初始化不当会导致“过钝”或“过激”的动力学，训练不稳
- **离散化敏感**：步长/容差同时影响精度与成本
- **生态不成熟**：`ncps` 库远不如 PyTorch 原生 RNN 成熟
- **可扩展性**：深层堆叠的长期信用分配与全局稳定性缺理论保证

## 五、对我们的适用性判断

### 支持做的理由
- dt 不规则 ✔（我们的第 0 维就是 dt，跨度 0.02s–3s）
- 时间尺度重要 ✔（玩家感受是“这一波很猛”+“这一下很难”两个尺度）
- CPU 部署 ✔
- 我们已有 `LiquidCell` 实现并通过 5 项自测（见 `tools/lnn_cell.py`）

### 反对做的理由（更强）
1. **LFM2 的实证**：液体算子在真机架构搜索里被淘汰，赢家是门控短卷积
2. **我们的 0.877**：岭回归与 34k 序列模型的残差相关 0.877，
   说明误差不来自模型表达能力——换单元改变不了这 0.877
3. **四次特征实验全灭**：屏幕坐标 / PhiraiAd 全对齐 / 手型五组 / 节奏时序
4. **我们的架构已经撞上了正确答案**：patch 嵌入（门控短卷积）+ biGRU + 注意力，
   **结构上就是 LFM2 搜索出来的形态**

### 唯一值得试的形态
如果一定要动，不是换掉 GRU，而是**把 τ 用在“多尺度”上**：

```
慢单元 τ≈5s   对应“这一段有多累”
快单元 τ≈0.5s 对应“这一下手怎么动”
```

这是 GRU 表达不了、而 LNN 天然能表达的东西（GRU 的 z 无量纲）。
但注意：**这属于“加特征”的精神，不是“换架构”。**

## 六、结论

```
不建议：用 LTC/CfC 替换 GRU              预期 Δρ ≈ 0，成本 4~7 小时
可以考虑：多尺度 τ（快/慢双单元）         预期 Δρ ±0.01，成本同上
更值得做：标签端（难度响应曲线已构造完成）  成本最低，信息增量最大
```

文献层面最有价值的一句话，不是任何一篇 LNN 论文，
而是 LFM2 那次搜索的结论：**架构的优势必须在目标硬件上量出来，纸上推的不算。**
这也正是我们这几个月反复踩的坑（换了两次架构，ρ 没动）。
