## 二、工具工作流

```
Phigros APK ──► resource.py ──► info/difficulty.tsv   ← 官谱定数（权威）
                │              info/info.tsv          ← 曲名/曲师/画师/谱师
                │              chart/{id}.0/{LEVEL}.json ← 官谱谱面（PGR 格式）
                │              music/{id}.ogg
                │              IllustrationLowRes/
                └──────────► phira.py ──► phira/{LEVEL}/{id}-{LEVEL}.pez
```

### 关键文件

| 文件 | 作用 |
|---|---|
| `resource.py` | 从 APK 提取全部资源，主入口 |
| `phira.py` | 把提取结果打包成适配 Phira 的 `.pez` |
| `typetree.json` | Unity typetree 定义（50KB） |
| `config.ini` | 资源类型开关 + 增量更新控制 |
| `requirements.txt` | `UnityPy==1.10.18`、`fsb5` |

### 定数来源（`resource.py:181`）

```python
with open("info/difficulty.tsv", encoding="utf8") as f:
```

`difficulty.tsv` 格式（从 `phira.py:44-50` 反推）：

```
<song_id>\t< EZ定数>\t< HD定数>\t< IN定数>\t< AT定数>\t...
```

`info.tsv` 格式（`phira.py:27-37`）：

```
<song_id>\t<曲名>\t<曲师>\t<画师>\t< EZ谱师>\t< HD谱师>\t< IN谱师>\t< AT谱师>
```

### 生成的pez 结构（`phira.py:66-90`）

```
{id}-{LEVEL}.pez
├── info.txt      # 注意是 .txt 不是 .yml
├── {id}.json     # 来自 chart/{id}.0/{LEVEL}.json
├── {id}.png      # 低画质曲绘
└── {id}.ogg      # 音乐
```

`info.txt` 内容模板：

```
Name: {曲名}
Song: {id}.ogg
Picture: {id}.png
Chart: {id}.json
Level: {LEVEL} Lv.{定数}
Composer: {曲师}
Illustrator: {画师}
Charter: {谱师}
```

⚠️ **注意格式差异**：这个工具生成的是 `info.txt`（Phira 早期格式），
而现代 Phira 用 `info.yml`（YAML）。`format` 字段需为 `null` 或明确指定。

## 三、执行步骤（需在有 APK 的环境）

### 0. 前置

```bash
pip install UnityPy==1.10.18 fsb5
```

并需要一个 Phigros APK（Android 端，`.apk` 或 `.xapk`）。

### 1. 放置 APK

把 APK 放到 `Phigros_Resource-master/` 目录，命名为 `phigros.apk`（或按 `main.py` 的参数指定）。

### 2. 先做增量提取（省时间）

`config.ini` 的 `[UPDATE]` 支持只提取新增歌曲：

```ini
[UPDATE]
main_story = 0      ; 主线前 N 首
other_song = 0      ; 单曲合集前 N 首
side_story = 0      ; 支线前 N 首
```

全量为 `0`。首次建议先设小值验证流程。

### 3. 生成 Phira 谱包

```bash
python phira.py
```

输出到 `phira/{EZ,HD,IN,AT}/{id}-{LEVEL}.pez`。

### 4. 我们真正需要的三份数据

| 目标 | 来源 | 用途 |
|---|---|---|
| **`info/difficulty.tsv`** | resource.py | **官谱定数标尺**（最关键） |
| **`chart/{id}.0/{LEVEL}.json`** | resource.py | 官谱谱面（PGR 格式） |
| `info/info.tsv` | resource.py | 曲名/谱师，用于交叉核对 |

**优先级**：即使只拿到 `difficulty.tsv` 也有价值 —— 它是官方定数的权威列表，
可直接作为社区谱模型的校准标尺。

---

## 四、官谱格式说明（PGR）

`.json` 谱面是 Phigros 原生格式，与 RPE 完全不同：

```
chart/{song_id}.0/{EZ|HD|IN|AT}.json
```

字段结构与 PEC 接近（绝对毫秒时间），但音符在 `judgeLineList[].notes*`，
且 `eventLayers` 结构不同。**这是第四种格式。**

拿到样本后需补充解析器 —— 参考 `prpr/src/parse.rs` 中 `Pgr` 分支。

---

## 五、MuMu 模拟器取 APK 的注意事项

1. **MuMu 里装 Phigros 后，APK 在**：
   - 根存储：`/sdcard/Android/data/org.pigeon.cygame.android/files/`
   - 或应用私有目录（需 root）
2. **包名**：`org.pigeon.cygame.android`
3. 也可直接从 TapTap 下载 APK（Phigros 国区仅 TapTap 渠道）
4. 部分版本资源在 **OBB** 或热更新包里，可能不止一个 APK

⚠️ **不要提取音频**。我们只要 `chart/*.json` 和 `info/difficulty.tsv`，
在 `config.ini` 里把 `music = false` 可以省大量时间和磁盘。

## 六、对项目的影响

**校准策略（双轨制）确认可行**：

```
官谱定数（difficulty.tsv）→ 标尺刻度
                            ↓
社区谱定数（9,685 张）    → 分布与离群识别
```

**理由**：官谱定数是官方人工指派但内部自洽（同一批谱师、同一套标准），
可用来定义「定数 15.3 应该对应什么样的谱面特征」。
社区谱定数有锚定效应污染（已实证），只能当分布看。

**在校准数据到位前，模型权重只能标注为「基于社区共识的假设」**，
不能对外声称是「客观难度」。
